## 2. 方案决策

### 2.1 自动保存：生命周期世代，而非取消 Promise

采用方案 A：在 `useAutosave` 中同时维护内容版本 `version` 与生命周期世代 `generation`。

- `version` 判断保存结果相对当前输入是否 stale。
- `generation` 判断保存结果是否仍属于当前条目或当前水合周期。
- `reset()` / `dispose()` 增加 generation；旧 Promise 可以自然完成，但不得更新状态或触发业务回调。
- `flush()` 返回时必须保证调用时已知的 dirty 工作已排空，或将当前失败抛给调用方。

不采用方案 B（每个组件自行比较 entry ID / revision），因为它会复制 stale 判断，并继续遗漏恢复、ABA 和 unmount 场景。

### 2.2 搜索：本地输入同步，列表请求 debounce

- AppShell 的输入事件同步写入本地 `searchQuery`，绝不等待详情保存。
- `entries.setQuery()` 保持同步状态更新 + 150 ms debounce 请求。
- 离开当前条目的行为（选条目、切视图、标签筛选、删除、退出）仍先 flush。
- 搜索不再隐式触发详情 flush；正在编辑的详情保持可见，列表结果按最新 query 更新。

这比为每次输入增加 request ID 更简单，也避免受控输入回退。

### 2.3 设置更新：单写队列 + 最新意图

- 所有设置写操作进入同一串行队列，避免两个响应互相覆盖整个 `AppSettings`。
- UI 立即反映最新意图；后端按队列顺序持久化。
- 单次失败只回滚该字段到最后一次成功快照，不回滚另一个已经成功的字段。
- 设置控件在自己的写入进行中禁用，防止重复点击造成无意义队列积压。

不只使用 request ID：后端系统自启动与数据库设置是副作用，丢弃旧响应不能阻止旧请求最后写入。

### 2.4 导出：由 Rust 选择目录

- `export_markdown` 不再接收 `target_dir`。
- 命令通过 `tauri_plugin_dialog::DialogExt` 在主窗口上下文调用目录选择器。
- 用户取消返回 `Ok(None)`；成功返回 `Ok(Some(ExportResult))`。
- 目录选择完成后再进入 `run_blocking` 查询和写文件。
- 前端移除 `dialog.open()` 和 `dialog:default` 权限，只调用 `exportMarkdown()`。

该方案把“目录由用户真实选择”绑定到可信端，优于在 Rust 中猜测允许的用户目录树。

### 2.5 Tauri 权限：运行时命令守卫 + 最小插件能力

Tauri 当前应用命令继续通过 `require_main_window` 限制调用窗口。Capability 用于最小化 `core` 与插件 API 权限：

- 主窗口只保留实际使用的 opener、window state 和必要 core API。
- Quick Capture 只保留窗口显示/隐藏、事件和必要 core API。
- 移除前端目录选择后不再授予 dialog 前端权限。
- 不虚构不存在的自定义 command capability；命令矩阵通过 Rust 单元测试和 Tauri 冒烟验证。

### 2.6 性能：有数据依据才改

旧计划已解决 FTS / LIKE 主路径。本轮只保留一个可独立验证、且不改变产品行为的低风险优化：`aliases_for_entries` 改为 `WHERE entry_id IN (...)`，避免导出或列表组装时读取无关 aliases。

LIKE term 上限、读连接池和流式重建均不在本轮直接实施。先通过现有 `knowledge-scale.ps1` 记录基线；只有出现可复现的超时、内存或查询计划问题，才另立性能设计与产品约束，不能在缺少数据时拒绝原本合法的搜索输入。

- [ ] **步骤 1：编写 inflight flush 失败测试**

新增用例：第 1 次保存处于 pending 时调用 `flush()`，期间再次 `markDirty()`；第 1 次完成后，第 2 次保存必须执行，外部 `flush()` 只在第 2 次完成后 resolve。

```ts
it("waits until changes queued during an in-flight save are persisted", async () => {
  const first = deferred<number>();
  const second = deferred<number>();
  const save = vi.fn().mockReturnValueOnce(first.promise).mockReturnValueOnce(second.promise);
  const autosave = useAutosave({ delay: 10, save });

  autosave.markDirty();
  const flushing = autosave.flush();
  autosave.markDirty();
  first.resolve(1);
  await Promise.resolve();

  expect(save).toHaveBeenCalledTimes(2);
  let finished = false;
  void flushing.then(() => (finished = true));
  expect(finished).toBe(false);

  second.resolve(2);
  await flushing;
  expect(autosave.state.value).toBe("saved");
});
```

let tagsRequestId = 0;
const tagsError = ref<string | null>(null);

async function refreshTags() {
  const requestId = ++tagsRequestId;
  tagsError.value = null;
  try {
    const next = await tagsList();
    if (requestId === tagsRequestId) {
      tags.value = next;
      tagsError.value = null;

  }
}

## 12. 风险与回滚策略

### 12.1 自动保存重构

**风险：** flush 循环无法结束、失败被吞、旧响应错误更新状态。

**控制：** generation 和 drain 先在 composable 单测完成；EntryDetail / QuickCapture 分别接入。每步单独提交。

**回滚：** 仅回滚任务 1 / 2 / 4 对应提交；不得回滚用户原有 UI 变更。

### 12.2 导出命令契约

**风险：** 原生 dialog 必须在正确线程执行；取消语义与错误语义混淆。

**控制：** dialog 选择与磁盘导出分层；取消为 `Ok(None)`；Rust helper 不依赖窗口，单测覆盖。

**回滚：** 恢复旧前端选择前，必须保留 Rust 目标目录校验，不能直接恢复任意字符串写入。

### 12.3 只读 SQLite 连接

**风险：** 某个现有 repo 错误地通过 `read_conn` 写数据，切换后测试暴露失败。

**控制：** 这是应修的架构违规；将写操作移到 `with_write_tx`，不放宽只读连接。

**回滚：** 仅允许临时保留 `PRAGMA query_only=ON` 而去掉 OS-level READ_ONLY flags，用于定位平台兼容问题；不得完全移除只读保护。

### 12.4 Capability 收紧

**风险：** 漏权限导致窗口功能失效。

**控制：** 静态 API 清单 + schema 校验 + Tauri build + 两窗口人工冒烟。

**回滚：** 按具体缺失 API 增加最小权限，不恢复 `*:default` 或 wildcard。

### 12.5 AppShell 拆分

**风险：** emit 命名、焦点恢复或响应式布局回归。

**控制：** 先锁定行为测试，再按单个组件逐步提取；不在同一任务修改 store。

**回滚：** 子组件逐提交，可按组件回滚；P0/P1 行为修复必须保留。
