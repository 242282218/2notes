# 2notes 产品方向设计

日期：2026-06-27

## 1. 产品定位

2notes 不是传统笔记软件，也不是纯待办软件。

它是一个面向个人的灵感与事务收集系统，用来承接用户脑子里、工作流里、剪贴板里不断出现的碎片信息，并帮助这些信息逐步变成可处理、可回顾、可积累的内容。

核心承诺：

> 不丢想法，不漏事务，不怕混乱。

第一阶段聚焦个人单机使用。产品现在和未来都不面向多人协作，不做团队空间、权限、共享、协同编辑等能力。

## 2. 核心问题

当前要解决的问题不是“写一篇漂亮的笔记”，而是：

- 灵感或待办经常突然出现，现有工具捕获成本高。
- Windows 记事本等临时记录方式缺少自动保存，容易丢内容。
- 不同类型事务混在一起，后续很难找回、澄清和处理。
- 剪贴板中有大量临时但可能有价值的信息，复制后经常无法回捞。

因此第一版优先解决：

- 快速记录。
- 自动保存。
- 事务状态。
- 基础整理。
- 剪贴板历史回捞。

## 3. 第一使用场景

最重要的使用场景是：

> 正在做别的事时，突然冒出一个想法或待办，要在 3 秒内保存，不打断当前工作。

理想流程：

1. 想到内容。
2. 呼出快速记录入口。
3. 输入内容。
4. 自动保存。
5. 回到原工作。

整理、分类、AI 总结、知识库沉淀都排在快速捕获之后。

## 4. 第一版成功标准

第一版满足以下 4 条即视为成功：

1. 任何时候能快速记录一条内容。
2. 内容不会因为没保存、崩溃、关窗口而丢。
3. 每条主动记录的内容都能标记当前状态。
4. 一周后还能把这些内容找回来、处理掉或沉淀下来。

第一版最终验收按以下 8 条判断：

1. 全局快捷键能在 Windows 任意场景呼出快速记录。
2. 快速记录 3 秒内可提交，成功后进入默认列表。
3. 崩溃或关闭不丢已提交内容和最后一份未提交草稿。
4. 主窗口能完成列表、详情编辑、类型、状态、标签、回收站。
5. 搜索能覆盖当前内容、原始内容、标签名，筛选支持类型、状态、标签。
6. SQLite 主存储、自动保存、备份、恢复、数据位置迁移都可用。
7. Markdown 全量导出可用，一条条目一个文件，带 YAML frontmatter。
8. 第一版不包含 AI、提醒日程、附件富文本、协作、多端同步、知识库链接解析。

## 5. 信息单位

第一版的最小信息单位是“条目/卡片”，不是传统文档。

每次快速记录生成一条独立条目。条目后续可以被澄清、标状态、分类、搜索、归档，并在长期方向中进入知识库或被 AI 整理。

主动条目提交时需要保存原始捕获内容。用户后续可以编辑条目的当前内容，但首次提交的原文应作为原始内容保留，不被编辑、整理或 AI 操作覆盖。第一版不做完整版本历史，只保留原始内容和当前内容两层。

第一版需要为后续知识库预留可选标题字段。标题不要求用户在快速捕获时填写，默认可从内容首行或摘要自动生成，用户后续可以编辑；没有标题时，列表仍显示内容摘要。

默认列表优先显示用户编辑过的标题；没有用户编辑过的标题时，显示内容摘要。自动生成标题不应强迫用户把快速捕获当成正式笔记命名。

快速记录生成的主动条目默认不要求立刻选择类型，初始类型为“未澄清”。用户后续整理时，再把它澄清为具体类型。

条目的“类型”和“状态”必须分开：

- 类型回答“这是什么”。
- 状态回答“现在怎么处理”。

二者不能混成一套字段，否则会限制后续表达。例如：一个问题可以被解决，一个资料可以被归档，一个灵感可以被沉淀。

第一版状态集合只保留三种：

- 待处理：还需要用户继续看、澄清或执行。
- 已完成：已经处理完，不再需要继续推进。
- 已归档：暂时不用，但保留可搜索和可回顾。

第一版不加入“处理中”。个人捕获工具里，中间状态容易变成额外维护负担；等后续出现明确执行看板需求时再考虑增加。

第一版主动条目的澄清后基础类型：

- 灵感：突然想到的点子、句子、方案。
- 任务：需要执行，有完成状态。
- 资料：链接、片段、参考信息。
- 问题：还没想清楚、需要后续追问或研究的东西。

## 6. 内容流转

核心流转方向：

> 捕获 → 澄清 → 处理 / 沉淀 / 归档

含义：

- 捕获：先随手丢进去，不要求立刻分类。
- 澄清：之后判断它是任务、灵感、资料还是问题；在此之前保持“未澄清”。
- 处理：任务类内容要推进。
- 沉淀：有长期价值的内容进入知识库方向。
- 归档：暂时不用但不删除，保留可搜索。

第一版主视角应围绕“收集箱 / 待澄清队列”，而不是传统笔记目录或日历待办。

第一版主窗口默认进入“待澄清收集箱”。这里展示用户主动记录但尚未处理完成的条目，按创建时间倒序排列，最新捕获在最上面。剪贴板流水作为独立入口存在，不进入默认主视图，避免被动捕获内容稀释主动收集箱。

默认列表按状态决定是否显示，而不是按类型。默认列表只显示“待处理”状态的主动条目，无论这些条目类型是未澄清、灵感、任务、资料还是问题。新提交条目默认状态为“待处理”；条目标记为“已完成”或“已归档”后，从默认列表消失，但仍可通过状态筛选找回。回收站是独立视图，不参与默认列表。

第一版左侧导航只保留 5 个入口：

- 收集箱。
- 搜索 / 全部。
- 标签。
- 回收站。
- 设置。

剪贴板流水不进入第一版主导航，保持独立边界，当前阶段不继续展开。

第一版主窗口采用“列表 + 详情面板”的结构。列表用于连续浏览和选择条目；详情面板用于编辑标题、当前内容、查看原始内容、修改类型、状态和标签。标题在详情面板顶部显示为可编辑输入，但不强制填写；正文仍然是主要编辑区。原始内容在详情面板中默认折叠，需要追溯时再展开查看。第一版不做单条内容独立详情页。

默认列表不按日期分组，第一版不做独立“今日”视图。条目可以显示创建日期作为上下文，但日期不作为第一版主要组织方式。

详情面板编辑当前内容时采用自动保存，不提供手动保存按钮。界面需要有轻量保存状态提示，例如“保存中 / 已保存 / 保存失败”，让用户知道内容是否已经落盘。

自动保存失败时，必须保留当前本地编辑态，明确提示失败，并持续重试或等待用户重新触发保存。不能静默丢弃用户输入，也不能把正在编辑的内容自动回滚成旧版本。

第一版设置页只放已确认能力的必要控制项：

- 全局快捷键。
- 开机自启动。
- 数据位置。
- 备份目录。
- 备份保留数量。
- 剪贴板监听开关。
- 导出 Markdown。

首次安装或初始化时，需要允许用户选择数据位置。主题、字体、布局、语言、云同步账号等不进入第一版设置。

第一版支持迁移数据位置。迁移前必须先备份当前 SQLite 数据库；迁移成功后再切换到新路径；迁移失败时继续使用原路径，不能进入半迁移状态。

第一版需要极简首次启动引导，只包含 3 步：

1. 选择数据位置。
2. 确认或修改全局快捷键。
3. 选择是否开启开机自启动。

首次启动引导不做产品介绍轮播，也不教育用户如何记笔记。

待澄清收集箱中，单条主动条目第一版只保留 4 个基础动作：

- 编辑内容。
- 修改类型。
- 改状态。
- 删除。

第一版需要支持标签。标签是条目从收集箱走向整理系统和知识库方向的核心扩展点，不应推迟到后续阶段。置顶、收藏、优先级等能力不进入第一版，避免让收集箱从“澄清处理队列”变成复杂管理系统。

第一版标签能力保持最小可用：

- 一条主动条目可以拥有多个标签。
- 标签用于整理、筛选和后续沉淀，不替代类型和状态。
- 标签采用自由输入 + 自动复用已有标签的交互。
- 用户编辑条目时可以直接输入标签；输入时提示已有标签，选中则复用，没有则创建新标签。
- 标签不做层级、颜色、图标、复杂管理页。
- 第一版不做标签重命名和标签合并。
- 标签可以后续扩展为主题、知识库分类或 AI 建议标签。

删除采用回收站机制。用户删除主动条目后，条目从默认视图消失并进入回收站；第一版需要提供回收站视图，用于查看误删内容并支持恢复。直接永久删除不作为默认删除行为。

永久删除只允许在回收站中发生。正常收集箱和整理视图中的删除动作都只移入回收站；回收站内可以对单条内容执行永久删除，后续再考虑是否提供清空回收站能力。

第一版搜索最低能力是全文搜索主动条目的当前内容、原始内容和标签名。这样能保证条目被编辑后，仍然可以通过首次捕获的表达找回，也可以通过标签找回相关内容。

第一版支持按类型、状态、标签进行基础筛选。筛选用于快速查看某类内容、某种处理状态或某个标签下的条目；第一版不做复杂查询语言或高级条件组合。

第一版支持最小批量操作。用户多选主动条目后，可以批量改状态、批量添加或移除标签、批量删除到回收站。第一版不做批量编辑正文、局部批量导出或批量合并。

## 7. 主动捕获

主动捕获是用户明确想记录的内容。

第一版推荐方向：

- 使用全局快捷键呼出极简输入框。
- 输入后自动保存。
- 默认进入收集箱 / 待澄清队列。
- 主窗口主要用于整理、搜索、改状态、回顾历史。
- 应用后台常驻，并提供系统托盘入口。

关闭主窗口不直接退出应用，而是最小化到系统托盘。托盘第一版提供打开主窗口、快速记录、暂停剪贴板监听和退出应用等基础动作。

第一版支持开机自启动，但默认关闭。用户可以在设置中手动开启或关闭。

快速记录的默认全局快捷键为 Ctrl + Alt + Space，并支持用户修改，避免与用户系统或其他软件快捷键冲突。

快速记录窗口默认显示在屏幕中央偏上，形态类似命令面板，不全屏，不承载复杂布局。它应短暂、明确、可预测，服务“输入后关闭并回到原工作”。

快速记录入口的键盘交互：

- Enter：提交当前内容，保存为一条主动条目，然后关闭快速入口。
- Shift+Enter：在当前输入中换行。
- Esc：取消本次输入并关闭快速入口。

第一版只做必要快捷键，不做完整快捷键系统：

- Ctrl + Alt + Space：呼出快速记录。
- Enter：快速记录提交。
- Shift + Enter：快速记录换行。
- Esc：关闭快速记录或取消当前浮层。
- Ctrl + F：聚焦搜索。

快速记录提交成功后，不弹系统通知。界面只在快速窗口内给极短成功反馈，然后关闭窗口，让用户回到原工作。

快速记录保存失败时，窗口不能关闭。必须保留输入内容，明确提示保存失败，并允许用户重试或复制内容。

快速记录入口不允许提交空内容。输入内容去掉首尾空白后为空时，不创建条目；界面可以给轻微反馈，但不弹出复杂错误。

快速记录入口需要支持“单份草稿恢复”。用户在快速入口中输入但尚未提交的内容，应随输入变化自动保存为最后一份草稿；提交成功后清空草稿；如果用户误关窗口、应用退出或崩溃，下次打开快速入口时恢复这份未提交草稿。

快速入口优先服务“记下并回去”，不是长文编辑器。多行内容可以支持，但默认动作必须偏向快速提交。

第一版内容形式以文本和链接为主：

- 一句话灵感。
- 一段想法。
- 一个待办描述。
- 一个链接和简短备注。

第一版不主打图片、附件、录音、网页剪藏、富文本排版。

第一版不支持附件、图片或截图粘贴。主动内容范围限定为文本和链接，先保证捕获、保存、整理、搜索和导出的闭环稳定。

第一版采用纯文本编辑。用户可以输入 Markdown 语法，但产品不提供富文本编辑器，也不做复杂 Markdown 预览；导出 Markdown 时按文本内容进入正文。

## 8. 剪贴板流水

剪贴板流水是被动捕获入口，和主动收集箱分开。

已确认方向：

- 默认开启剪贴板历史。
- 永久保存所有文本和链接类剪贴板内容。
- 剪贴板流水不直接进入收集箱。
- 剪贴板流水是可回捞的安全网，不是每天必须处理的待办队列。

剪贴板流水的角色：

- 自动保存复制过的文本和链接。
- 需要时可以搜索和回捞。
- 后续 AI 可以从中发现可能值得沉淀的内容。
- 不应把大量剪贴板内容压到主收集箱里，避免制造新的处理负担。

剪贴板流水只保存复制当时的原始内容，不提供编辑态，也不维护“原始内容 + 当前内容”两层结构。剪贴板流水保持独立，不进入收集箱主流程；当前阶段不继续展开剪贴板与主动条目的转换关系。

该方向存在明确隐私风险：剪贴板可能包含密码、验证码、Token、私聊内容或其他敏感信息。产品方向上仍坚持默认开启和永久保存，但后续实现设计必须认真处理本地掌控、清理、暂停、搜索和敏感信息风险提示。

## 9. 状态边界

第一版不主打提醒、截止时间、重复任务或日程通知。

原因：

- 当前核心不是替代日历或 Todoist。
- 第一阶段目标是先保证内容不会丢，并能被澄清和处理。
- 过早加入提醒和日程会把产品带向复杂待办软件，稀释“灵感与事务收集系统”的核心。

第一版可以保留“这是一个任务”的语义，但不把提醒能力作为主线。

任务类型第一版不增加截止时间、优先级等独立字段。任务只是主动条目的类型之一，是否完成由状态表达。

## 10. 知识库方向

第二版目标是逐步演进到类 Obsidian 的本地知识库能力。

知识库方向不作为第一版必须完成的范围，但它是第一版之后的下一阶段主线。AI 接入至少要等知识库能力开发完毕之后再考虑。

第二版知识库方向中，条目本身应能沉淀为知识库节点，而不是从条目复制出另一份笔记。第一版条目是捕获态；第二版在同一条目实体上增加知识库组织能力，让它逐步从收集箱 item 演进为知识节点。

第一版允许用户在纯文本中输入类似 `[[标题]]` 的双链语法，但不解析、不建立链接关系，也不提供反向链接面板。第一版只保证不破坏这类文本，为第二版知识库能力预留空间。

长期可能包含：

- 本地知识库。
- 双链或反向链接。
- 标签和主题沉淀。
- 全文搜索。
- 类 Obsidian 的组织能力。
- AI 自动整理和关联发现。

第一版必须为这个方向留出产品空间，但当前不提前锁定具体实现细节。

第一版本地存储采用 SQLite 作为主存储。主动条目的类型、状态、标签、原始内容、当前内容、回收站、搜索和自动保存状态都属于结构化数据，优先用 SQLite 保证一致性和查询能力。Markdown 文件不作为第一版主存储，后续再用于导出、沉淀或知识库方向。

第一版需要做最小自动备份：定期把 SQLite 数据库复制到本地备份目录，默认保留最近 10 份备份，并支持用户配置保留数量。备份频率为每天一次：应用启动时检查，如果距离上次成功备份超过 24 小时，就创建一份新备份。第一版需要提供“从备份恢复”的入口。从备份恢复前，应用必须先自动备份当前 SQLite 数据库，生成恢复前快照；恢复失败时保留当前库，不能进入半恢复状态。第一版先实现本地备份，不做云同步；但备份设计需要预留后续扩展到 Google Drive、OneDrive、Dropbox 或其他云盘的空间。

第一版不做数据库加密和应用锁。产品必须明确展示本地数据存储位置，并对剪贴板、主动记录中可能包含敏感数据给出风险提示。加密、应用锁和密钥管理后续需要成体系设计，不能在第一版做半成品。

产品是个人自用、本地优先工具，永远不上传用户数据。第一版可以做本地日志用于排查问题，但不做远程错误上报、遥测、分析埋点或任何形式的数据上传。日志只保存在用户本机，并在设置页提供打开日志目录的入口。

第一版需要做最小导出：将全部主动条目导出为 Markdown 文件夹。导出时一条主动条目对应一个 Markdown 文件。导出文件名采用“创建时间-内容摘要.md”，例如“2026-06-28-143012-整理2notes标签规则.md”。文件名需要清理非法字符，摘要过长时截断。导出用于数据可迁移性和后续知识库沉淀，不作为第一版主存储。

导出的 Markdown 文件需要包含 YAML frontmatter，用于保存结构化元数据：id、type、status、tags、created_at、updated_at。正文保存条目的当前内容；原始内容放在正文后的分隔区，便于追溯但不干扰主要阅读。

第一版不支持从 Markdown 反向导入。导出用于数据可迁移和知识库沉淀，不承诺外部修改后的 Markdown 能无损回流到 SQLite 主库。

## 11. AI 权限边界

第一版不做任何 AI 功能。AI 接入不早于第三版，必须建立在第二版知识库能力完成之后。

后续 AI 自动整理的原则：

> AI 帮用户从混乱中提炼秩序，但不能擅自改掉用户的原始想法。

AI 可以做：

- 建议标签。
- 建议分类。
- 生成摘要。
- 发现关联。
- 提醒待处理内容。
- 从剪贴板流水中发现可能有价值的内容。

AI 不应做：

- 覆盖原始记录。
- 删除原始内容。
- 静默改变重要状态。
- 让整理结果不可追溯。

AI 产生的整理结果应可撤销、可追溯，重要变更需要用户确认。

## 12. 明确不做

第一版不做：

- AI。
- 知识库链接解析 / 反向链接。
- 多端同步。
- 云备份实际接入。
- 自动更新。
- 加密 / 应用锁。
- 附件 / 图片 / 截图。
- 富文本编辑器。
- 提醒 / 日程 / 截止时间 / 优先级。
- 协作 / 账号 / 登录。
- 标签重命名 / 合并。
- Markdown 反向导入。
- 远程上报 / 遥测 / 数据上传。
- 权限管理。
- 团队空间。
- 协同编辑。
- 插件系统。
- Canvas。
- 图谱可视化。
- 完整 Obsidian 级知识库。

这些排除项用于保护第一版目标：快速捕获、自动保存、状态澄清、可搜索回捞。

## 13. 阶段划分

第一阶段：个人捕获系统

- Windows 桌面端优先。
- 技术路线采用 Tauri + Vue 3 + TypeScript + SQLite；Rust 负责本地能力与数据层，Vue 负责界面与交互。
- 提供 Windows 安装包，但第一版不做自动更新。
- 快速记录。
- 自动保存。
- 收集箱 / 待澄清队列。
- 条目状态。
- 文本和链接为主。
- 剪贴板流水。
- 搜索和回捞。

第二阶段：本地知识库方向

- 类 Obsidian 的组织能力。
- 知识沉淀。
- 关联发现。
- 更强全文搜索。

第三阶段：AI 自动整理

- 嵌入模型接入。
- 自动标签和主题建议。
- 内容聚类。
- 摘要生成。
- 待处理内容发现。

第四阶段：多端与备份

- 自动备份。
- 安卓端同步。
- 跨端一致性。
- 与 files.md 或机器人交互。

## 14. 当前共识

已确认方向：

- 产品是个人灵感与事务收集系统。
- 核心承诺是不丢想法、不漏事务、不怕混乱。
- 第一使用场景是 3 秒内捕获，不打断当前工作。
- 最小单位是条目/卡片。
- 主动条目默认类型为未澄清，后续可澄清为灵感、任务、资料、问题。
- 类型和状态分离；第一版状态为待处理、已完成、已归档。
- 主窗口默认进入待澄清收集箱，默认列表按状态显示待处理条目，按创建时间倒序排序。
- 主窗口采用列表 + 详情面板，不做独立详情页。
- 第一版支持标题、当前内容、原始内容、类型、状态、标签、回收站、搜索和基础筛选。
- 第一版支持标签，但不做标签重命名、合并、层级、颜色、图标和复杂管理页。
- 第一版支持最小批量操作：批量改状态、批量加 / 移除标签、批量删除到回收站。
- 第一版不主打提醒、日程、截止时间和优先级。
- 内容以文本和链接为主。
- 第一版纯文本编辑，允许用户输入 Markdown 语法，但不做富文本编辑器和复杂 Markdown 预览。
- 默认永久保存剪贴板文本和链接历史。
- 剪贴板流水和收集箱分开。
- 剪贴板流水是可回捞的安全网。
- 第一版技术路线采用 Tauri + Vue 3 + TypeScript + SQLite；Rust 负责本地能力与数据层，Vue 负责界面与交互。
- 第一版是 Windows 桌面端优先，支持后台常驻、系统托盘、全局快捷键和开机自启动开关。
- SQLite 是第一版主存储；支持自动保存、本地备份、备份恢复、数据位置选择和迁移。
- 第一版支持全部主动条目导出为 Markdown 文件夹，一条条目一个文件，带 YAML frontmatter。
- 产品是个人自用、本地优先工具，永远不上传用户数据。
- 第一版不做 AI；第二版目标是本地知识库，第三版再考虑 AI。
- 永久个人工具，不做多人协作、账号体系、权限管理、团队空间和协同编辑。
