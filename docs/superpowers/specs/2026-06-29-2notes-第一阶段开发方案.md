## 1. 阶段定义

第一阶段只做个人 Windows 桌面端的主动捕获 MVP：

> 快速记录 -> 可靠保存 -> 收集箱处理 -> 基础搜索筛选 -> 回收站保护 -> Markdown 导出

本阶段真正验证的是：

1. 用户能在工作中快速记下一条内容。
2. 已提交内容和最后一份未提交草稿不会因为关窗口或重启丢失。
3. 用户能在主窗口把条目找回来、改状态、打标签、删除或从回收站恢复。
4. 用户能把全部未永久删除的主动条目导出为 Markdown。

本阶段不做完整知识库，不做 AI，不做多端同步，不做云备份，不做附件、富文本、图谱、Canvas、提醒、日程和协作。

剪贴板流水完全不进入第一阶段。文档、托盘、设置页和命令合同中都不保留剪贴板开关或“暂停剪贴板”入口，避免出现不可用的伪功能。

备份、恢复、数据位置迁移拆开处理：

- 第一阶段可以生成本地安全快照，用于降低开发和试用期的数据风险。
- 第一阶段不实现应用内从备份恢复。
- 第一阶段不实现数据位置迁移。
- 恢复和迁移进入后续“数据安全专项阶段”，必须单独设计原子替换、连接关闭、WAL/SHM、失败回滚和验收脚本。

## 2. 成功标准

本阶段完成后，必须满足以下硬标准：

1. 普通 Windows 桌面会话中，全局快捷键注册成功时可以呼出快速记录窗口；快捷键冲突时不影响主窗口和数据访问，并在设置页展示失败状态。
2. 快速记录 trim 后非空即可提交，成功后进入默认收集箱。
3. 快速记录输入变化会保存最后一份草稿；关窗口或应用重启后可恢复。
4. 已提交条目和详情编辑内容不会因为关闭窗口或应用重启丢失。
5. 主窗口能完成列表、详情编辑、类型、状态、标签、单条删除、回收站恢复、回收站永久删除。
6. 搜索覆盖标题、当前内容、原始内容、标签名；筛选支持类型、状态、标签。
7. SQLite 主存储、schema 迁移、自动保存、本地日志、Markdown 全量导出可用。
8. 关闭主窗口后应用留在托盘，退出只能通过托盘或明确退出动作。
9. 日志不记录完整条目内容、草稿内容或敏感正文。
10. `pnpm run lint`、`pnpm run typecheck`、`pnpm run test:unit`、`pnpm run build`、`cargo test --manifest-path src-tauri/Cargo.toml`、`cargo clippy --manifest-path src-tauri/Cargo.toml --all-targets --all-features -- -D warnings` 必须通过。

以下内容不是第一阶段硬标准：

- 批量操作。
- 应用内备份恢复。
- 数据位置迁移。
- 剪贴板流水。
- Windows 安装包发布。
- FTS5 全文索引。
- 标签重命名、合并、颜色、层级。

## 3. 开源参照与复用策略

第一阶段只吸收开源项目中的原则，不复制业务代码。

可借鉴的原则：

| 来源 | 借鉴点 | 第一阶段落地 |
| --- | --- | --- |
| Tauri | 桌面壳、窗口、托盘、系统能力 | 使用 Tauri 2 和官方插件，不手写 Windows 胶水 |
| SQLite | 本地结构化存储 | 作为唯一主存储，保证条目、标签、草稿一致性 |
| Joplin / QOwnNotes | 数据主权、可导出 | Markdown 全量导出，一条主动条目一个文件 |
| Logseq / Foam | 原子化信息单位 | 快速记录生成独立条目，不做文档树 |
| SiYuan / Trilium | 结构化属性 | 保留 `type/status/tags`，不做块编辑器 |

不进入本阶段的参照方向：

- Obsidian / Logseq 的双链、图谱、大纲。
- Joplin 的同步和 E2EE。
- AFFiNE / AppFlowy 的工作区、画布、协作。
- Anytype 的对象系统和 P2P。
- SiYuan 的块级数据库和发布能力。

## 4. 推荐实现路线

### 4.1 方案对比

| 方案 | 做法 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| A. Rust 数据层 + Vue 交互层 | Vue 通过 Tauri commands 调 Rust；Rust 负责 SQLite、文件、导出、日志 | 边界清晰，SQL 不泄漏到 UI，数据写入可控 | Rust command 和 DTO 要写完整 | 采用 |
| B. Tauri SQL plugin 让前端直接访问 SQLite | 前端直接 CRUD | 初期代码少 | UI 知道表结构，自动保存、导出、回收站边界变差 | 不采用 |
| C. Markdown 文件作为主存储 | 每条条目直接写 `.md` | 数据主权强 | 状态、标签、草稿、回收站和搜索一致性复杂 | 不采用 |

本阶段采用方案 A：`Tauri + Vue 3 + TypeScript + SQLite`。Rust 是唯一数据写入边界，Markdown 只作为导出格式。

### 4.2 关键取舍

- 数据库连接：第一阶段不使用 `r2d2` 连接池。使用一个 `rusqlite::Connection` 包在 `Mutex` 中，或使用单线程 DB actor。单用户桌面应用先保证事务边界和恢复简单性。
- 事务边界：组合写操作必须在同一个事务内完成。Repo 不允许自己随意获取新连接。
- 搜索：第一阶段先用安全转义后的 `LIKE` 覆盖标题、当前内容、原始内容和标签名。个人数据量下足够可用。FTS5 后移到数据量或性能证明需要时再加。
- 迁移：可以使用 `rusqlite_migration`，或实现极小 migration runner，但必须记录 `version`、`checksum`、`applied_at`。迁移脚本不滥用 `CREATE TABLE IF NOT EXISTS` 掩盖错误 schema。
- 单实例：必须加入 `tauri-plugin-single-instance`。第二个进程只把“打开主窗口/打开快速记录”的意图转发给第一个进程。
- 日志：第一阶段只选一套日志栈。推荐 `log + tauri-plugin-log`。日志只写操作、ID、错误码和脱敏错误，不写正文和草稿。
- Markdown frontmatter：不手写 YAML 转义。使用维护中的 YAML 库，或改用 TOML frontmatter。导出测试必须能 parse 回读元数据。

## 7. 数据层方案

### 7.1 启动路径

第一阶段不做首次启动引导，不让数据目录选择阻塞 MVP。启动时自动使用 Tauri app data 目录。

启动顺序：

1. 初始化日志。
2. 注册单实例插件。
3. 读取 Tauri app config 目录下的 `bootstrap.json`。
4. 如果没有 `bootstrap.json`，写入默认 `data_dir`。
5. 创建 `data_dir`。
6. 打开 SQLite：`2notes.sqlite`。
7. 设置 PRAGMA。
8. 执行迁移。
9. 注册托盘和默认全局快捷键。
10. 打开主窗口。

`bootstrap.json` 示例：

```json
{
  "data_dir": "D:\\Users\\<user>\\AppData\\Roaming\\2notes\\data"
}
```

规则：

- `data_dir` 的真实来源是 `bootstrap.json`。
- 第一阶段设置页只展示数据目录和提供“打开数据目录”。
- 数据位置选择和迁移后移。

### 7.2 SQLite PRAGMA

打开连接后执行：

```sql
PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;
PRAGMA busy_timeout = 5000;
PRAGMA synchronous = NORMAL;
```

说明：

- `foreign_keys` 保证标签关系不悬空。
- WAL 提升桌面读写体验。
- `busy_timeout` 避免自动保存和列表查询短暂冲突时立刻失败。
- `synchronous = NORMAL` 在 WAL 下平衡可靠性和速度。

### 7.3 初始迁移

`001_init.sql`：

```sql
CREATE TABLE schema_migrations (
  version INTEGER PRIMARY KEY,
  checksum TEXT NOT NULL,
  applied_at TEXT NOT NULL
);

CREATE TABLE entries (
  id TEXT PRIMARY KEY,
  title TEXT NULL,
  title_source TEXT NOT NULL CHECK (title_source IN ('auto', 'user')),
  original_content TEXT NOT NULL,
  current_content TEXT NOT NULL,
  type TEXT NOT NULL CHECK (type IN ('unclear', 'idea', 'task', 'material', 'question')),
  status TEXT NOT NULL CHECK (status IN ('pending', 'done', 'archived')),
  revision INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  deleted_at TEXT NULL
);

CREATE INDEX idx_entries_status_deleted_created
  ON entries(status, deleted_at, created_at DESC);

CREATE INDEX idx_entries_type
  ON entries(type);

CREATE INDEX idx_entries_deleted_at
  ON entries(deleted_at);

CREATE TABLE tags (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,
  normalized_name TEXT NOT NULL UNIQUE,
  created_at TEXT NOT NULL
);

CREATE TABLE entry_tags (
  entry_id TEXT NOT NULL REFERENCES entries(id) ON DELETE CASCADE,
  tag_id TEXT NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
  PRIMARY KEY (entry_id, tag_id)
);

CREATE INDEX idx_entry_tags_tag_id
  ON entry_tags(tag_id);

CREATE TABLE settings (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

CREATE TABLE drafts (
  id TEXT PRIMARY KEY,
  content TEXT NOT NULL,
  revision INTEGER NOT NULL DEFAULT 0,
  updated_at TEXT NOT NULL
);
```

第一阶段不创建 FTS 表，不创建 `backup_records` 表。备份快照记录如果需要，写到备份目录的 manifest JSON，避免恢复旧库时把备份历史一起回滚。

### 7.4 迁移 runner

实现位置：`src-tauri/src/db/migrations.rs`

职责：

- 内嵌 `schema/*.sql`。
- 计算迁移文件 checksum。
- 启动事务。
- 读取 `schema_migrations`。
- 按版本顺序执行未应用迁移。
- 每个迁移成功后插入 `schema_migrations(version, checksum, applied_at)`。
- 已应用版本 checksum 不一致时拒绝启动。
- 数据库版本高于当前应用支持版本时拒绝启动。
- 任一迁移失败时回滚，不进入主界面。

不要做 down migration。第一阶段只需要向前迁移和失败保护。

### 7.5 Repo 边界

Repo 层只处理数据库，不知道 Tauri 窗口、托盘和前端状态。

组合写操作必须共享同一个事务。推荐接口形态：

```rust
EntriesRepo
  create(tx, content, now) -> Entry
  list(conn, filter, page) -> Page<EntryListItem>
  get(conn, id) -> EntryDetail
  update(tx, id, patch, expected_revision, now) -> EntryDetail
  move_to_trash(tx, id, now) -> EntryDetail
  restore_from_trash(tx, id, now) -> EntryDetail
  delete_forever(tx, id) -> ()

TagsRepo
  suggest(conn, query) -> Vec<Tag>
  list(conn) -> Vec<Tag>
  resolve_many(tx, names, now) -> Vec<Tag>
  replace_entry_tags(tx, entry_id, tag_names, now) -> Vec<Tag>

DraftsRepo
  get(conn) -> Draft
  update(tx, content, expected_revision, now) -> Draft
  clear(tx, now) -> ()
```

标签规范化：

- `normalized_name = trim(name).to_lowercase()`。
- trim 后为空的标签直接忽略。
- 同一次保存内重复标签去重。
- 第一阶段不做标签重命名、合并、颜色、图标、层级。

### 7.6 搜索策略

第一阶段搜索必须保证中文可用，也必须保证用户输入不会污染 SQL 语义。

执行策略：

1. 查询为空时走普通列表过滤。
2. 查询非空时统一使用转义后的 `LIKE`：

```sql
WHERE
  entries.title LIKE :q ESCAPE '\'
  OR entries.current_content LIKE :q ESCAPE '\'
  OR entries.original_content LIKE :q ESCAPE '\'
  OR EXISTS (
    SELECT 1
    FROM entry_tags et
    JOIN tags t ON t.id = et.tag_id
    WHERE et.entry_id = entries.id
      AND t.name LIKE :q ESCAPE '\'
  )
```

3. `%`、`_`、`\` 必须转义。
4. 列表和搜索 command 必须带 `limit` 和 `offset`，默认 `limit = 50`。

后续只有在数据量或体验证明需要时，再引入 SQLite FTS5 或 Tantivy。

## 8. Tauri command 合同

所有 command 返回 `Result<T, AppErrorResponse>`，对外错误结构：

```ts
type AppErrorResponse = {
  code: string
  message: string
  recoverable: boolean
}
```

规则：

- `message` 给 UI 展示，必须可读且脱敏。
- `code` 给前端判断，例如 `VALIDATION_EMPTY_CONTENT`、`DB_MIGRATION_FAILED`、`SHORTCUT_REGISTER_FAILED`、`REVISION_CONFLICT`。
- 不把 SQL、完整路径、条目正文、草稿内容直接返回给 UI。
- Rust 内部错误保留根因，但日志只写 command 名、entry id、错误码和 source error。
- 应用维护态统一返回 `APP_MAINTENANCE`。第一阶段暂不做恢复/迁移，但为后续留出合同。

Commands：

```text
entries_create(content)
entries_list(filter, page)
entries_get(id)
entries_update(id, patch, expected_revision)
entries_move_to_trash(id)
entries_restore_from_trash(id)
entries_delete_forever(id)

tags_suggest(query)
tags_list()

settings_get()
settings_update(patch)

draft_get()
draft_update(content, expected_revision)
draft_clear()

export_markdown(target_dir)

window_open_main()
window_open_quick_capture()
window_hide_quick_capture()
window_hide_main()
app_quit()
```

DTO 生成：

- Rust 类型定义在 `src-tauri/src/types/`。
- 使用 `ts-rs` 导出到 `src/types/generated.ts`。
- 前端 service 层只 import 生成类型，不复制枚举字符串。

## 9. 前端实现方案

### 9.1 路由和窗口

第一阶段不需要复杂路由。用 `routes.ts` 管理视图状态：

- `inbox`
- `search`
- `tags`
- `trash`
- `settings`
- `quick-capture`

主窗口渲染 `AppShell`，快速记录窗口渲染 `QuickCapture`。通过窗口 label 判断当前入口，避免两个窗口加载同一套重 UI。

### 9.2 状态存储

`stores/entries.ts`：

- 当前导航视图。
- 当前 filter。
- 列表项。
- 当前选中 entry id。
- 详情数据。
- 列表加载/保存/失败状态。
- 当前分页状态。

`stores/settings.ts`：

- 全局快捷键注册状态。
- 开机自启动开关。
- 数据目录。
- 日志目录。

### 9.3 自动保存状态机

实现位置：`src/composables/useAutosave.ts`

状态：

```text
idle -> dirty -> saving -> saved
                 saving -> failed
failed -> dirty -> saving
```

规则：

- 输入变化后本地状态立即更新。
- debounce 500ms 后调用保存。
- 保存请求携带本地 revision。
- 保存中再次输入，当前请求不取消，但返回后如果 revision 已过期，不覆盖 UI。
- 服务端发现 `expected_revision` 不匹配时返回 `REVISION_CONFLICT`，前端提示重新加载或重试。
- 保存失败时保留用户输入，显示失败，下一次输入或点击重试再次保存。

### 9.4 快速记录窗口

组件：`QuickCapture.vue`

行为：

- 打开时调用 `draft_get()`。
- 输入变化 debounce 250ms 调 `draft_update(content, expected_revision)`。
- `Enter` 提交。
- `Shift+Enter` 换行。
- `Esc` 隐藏窗口但不清空草稿。
- trim 后为空不创建条目。
- `entries_create` 成功后调 `draft_clear()`。
- 失败时窗口不关闭，显示错误和“重试 / 复制”动作。

提交顺序：

1. 前端 trim 校验。
2. 调 `entries_create(trimmedContent)`。
3. 成功后调 `draft_clear()`。
4. 显示极短“已保存”。
5. 调 `window_hide_quick_capture()`。

Rust 侧仍必须再次校验空内容，不能只信前端。

### 9.5 主窗口

布局：

- 左侧固定导航：收集箱、搜索 / 全部、标签、回收站、设置。
- 中间列表：条目摘要、类型、状态、标签、创建时间。
- 右侧详情：标题、当前内容、原始内容折叠、类型、状态、标签、保存状态。

默认查询：

- `status = pending`
- `deleted_at IS NULL`
- `ORDER BY created_at DESC`
- `limit = 50`

列表项不要展示过多正文；默认用标题或内容摘要。

### 9.6 第一阶段不做的交互

第一阶段不做：

- 批量改状态。
- 批量添加或移除标签。
- 批量移入回收站。
- 批量永久删除。
- 批量导出。
- 标签重命名或合并。

这些能力等用户产生足够条目后再判断是否值得做。

## 10. 导出和本地安全快照

### 10.1 Markdown 导出

导出范围：

- 全部未永久删除的主动条目。
- 包含 pending、done、archived。
- 包含回收站条目，因为它们尚未永久删除。

如果条目在回收站，frontmatter 写入 `deleted_at`。用户不希望导出回收站内容时，应先永久删除对应条目；导出命令不静默丢弃可恢复数据。

文件名：

```text
YYYY-MM-DD-HHMMSS-内容摘要.md
```

冲突处理：

- Windows 非法字符用 `sanitize-filename` 清理。
- 摘要过长截断到 40 个字符。
- 空摘要使用 `untitled`。
- 同名追加短 ID。

内容结构：

```markdown
---
id: "entry-id"
type: "idea"
status: "pending"
tags:
  - "标签"
created_at: "2026-06-29T10:00:00+08:00"
updated_at: "2026-06-29T10:05:00+08:00"
deleted_at: null
---

# 标题或内容摘要

当前内容

---

## 原始内容

首次捕获内容
```

测试必须覆盖：

- Windows 非法字符。
- 同名冲突。
- 空标题 / 空摘要。
- 多标签。
- 特殊字符能被 frontmatter parser 回读。
- 原始内容与当前内容不同。

### 10.2 本地安全快照

第一阶段允许实现“只生成不恢复”的本地安全快照：

1. 启动时如果距离上次快照超过 24 小时，创建一份 SQLite backup API 快照。
2. 快照文件写到默认备份目录。
3. 快照 manifest 写到备份目录，例如 `backups.json`。
4. 默认保留最近 10 份 daily 快照。

规则：

- 快照失败只记录日志并在设置页提示，不阻止主窗口使用。
- 第一阶段不提供应用内恢复按钮。
- 第一阶段不提供数据位置迁移。
- 不把快照历史写进主数据库。

如果实现成本超过预期，本节可后移；Markdown 导出仍是第一阶段必须完成的数据可迁移能力。

创建 `.github/workflows/ci.yml`：

```yaml

  push:
  pull_request:

jobs:
  frontend:
    runs-on: windows-latest
    steps:
      - uses: actions/checkout@v4
      - uses: pnpm/action-setup@v4
        with:
          version: 10
      - uses: actions/setup-node@v4

      - run: pnpm run lint
      - run: pnpm run typecheck
      - run: pnpm run test:unit
      - run: pnpm run build

  rust:
    runs-on: windows-latest

      - uses: actions/checkout@v4
```

- 本阶段不需要测试机。

| 风险 | 触发点 | 处理 |
| --- | --- | --- |
| 第一阶段再次膨胀 | 想提前做知识库、剪贴板、恢复、迁移、批量 | 按“不做”列表截断 |

| Markdown frontmatter 损坏 | 标签或内容包含特殊字符 | 使用库生成，并 parse 回读测试 |
| AGPL/GPL 代码污染 | 复制 Joplin/Logseq 等代码 | 只借鉴设计，不复制代码 |
