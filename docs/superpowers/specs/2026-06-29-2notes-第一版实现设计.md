# 2notes 第一版实现设计

日期：2026-06-29

来源文档：[2026-06-27-2notes-产品方向设计.md](./2026-06-27-2notes-产品方向设计.md)

## 1. 实现目标

第一版只实现个人 Windows 桌面端的主动捕获闭环：

> 快速记录 → 自动保存 → 收集箱处理 → 搜索筛选 → 回收站保护 → 本地备份恢复 → Markdown 导出

第一版硬验收标准沿用产品方向文档中的 8 条，不额外扩大范围。实现时优先保证“不丢内容”和“能找回来”，再打磨界面细节。

剪贴板流水保持独立边界，不进入收集箱主流程，也不作为本实现设计的主线展开。第一版实现以主动条目闭环为准；剪贴板模块只保留接口边界，不纳入本实现设计的验收范围。

## 2. 技术路线

采用 `Tauri + Vue 3 + TypeScript + SQLite`：

- Vue 3 + TypeScript：主窗口、快速记录窗口、设置页、列表筛选、详情面板等界面交互。
- Rust / Tauri：系统托盘、全局快捷键、窗口管理、SQLite、文件系统、备份恢复、Markdown 导出、本地日志。
- SQLite：本地结构化主存储。

### 方案取舍

推荐方案是 Tauri + Vue，而不是纯 Rust UI 或 Electron：

- 纯 Rust UI 更轻，但标签输入、筛选、详情面板、设置页等交互开发成本更高。
- Electron UI 生态成熟，但常驻内存和包体更重，不符合个人本地工具气质。
- Tauri + Vue 能把 Rust 放在系统能力和数据层，把 Vue 放在高频交互层，是第一版最稳的平衡点。

边界原则：

- Vue 不直接拼 SQL，只通过 Tauri command 调用 Rust。
- Rust command 不处理复杂 UI 状态，只做输入校验、持久化和系统能力。
- SQLite repo 层只处理数据读写，不知道窗口、托盘和前端概念。
- 文件系统操作集中在 `files/` 和 `system/`，避免散落到业务命令里。

## 4. 数据模型

### 4.1 主动条目

`entries`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | TEXT PRIMARY KEY | UUID |
| title | TEXT NULL | 用户编辑标题，可为空 |
| title_source | TEXT NOT NULL | `auto` 或 `user` |
| original_content | TEXT NOT NULL | 首次提交内容，不覆盖 |
| current_content | TEXT NOT NULL | 当前可编辑内容 |
| type | TEXT NOT NULL | `unclear` / `idea` / `task` / `material` / `question` |
| status | TEXT NOT NULL | `pending` / `done` / `archived` |
| created_at | TEXT NOT NULL | ISO 8601 |
| updated_at | TEXT NOT NULL | ISO 8601 |
| deleted_at | TEXT NULL | 进入回收站时间 |

约束：

- 新建条目默认 `type = unclear`、`status = pending`。
- 删除只写入 `deleted_at`，默认查询排除已删除。
- 永久删除只允许从回收站执行。
- `original_content` 创建后不通过普通编辑接口更新。

### 4.2 标签

`tags`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | TEXT PRIMARY KEY | UUID |
| name | TEXT NOT NULL | 用户看到的标签名，保留原始大小写 |
| normalized_name | TEXT NOT NULL UNIQUE | 用于复用和去重，规则为 trim 后转小写 |
| created_at | TEXT NOT NULL | 创建时间 |

`entry_tags`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| entry_id | TEXT NOT NULL | 条目 ID |
| tag_id | TEXT NOT NULL | 标签 ID |

约束：

- 一条条目可有多个标签。
- 编辑条目时自由输入标签；按 `normalized_name` 查找，已有则复用，没有则创建。
- 第一版不做标签重命名、合并、层级、颜色、图标。

### 4.3 设置

`settings`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| key | TEXT PRIMARY KEY | 设置键 |
| value | TEXT NOT NULL | JSON 或字符串值 |
| updated_at | TEXT NOT NULL | 更新时间 |

必要设置：

- `backup_dir`
- `backup_retention_count`，默认 `10`
- `global_shortcut`，默认 `Ctrl+Alt+Space`
- `start_on_boot`，默认 `false`
- `clipboard_enabled`
- `first_run_completed`

数据位置不能只存在 SQLite 里。应用启动前需要先读取一个轻量 bootstrap 配置文件，例如 Tauri app config 目录下的 `bootstrap.json`，其中保存 `data_dir`。SQLite 中可以镜像展示数据位置，但真实启动路径以 bootstrap 配置为准。

### 4.4 草稿

`drafts`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | TEXT PRIMARY KEY | 固定为 `quick_capture` |
| content | TEXT NOT NULL | 最后一份快速记录草稿 |
| updated_at | TEXT NOT NULL | 更新时间 |

约束：

- 只保存快速记录入口的最后一份未提交草稿。
- 提交成功后清空草稿。
- 应用重启或快速入口重新打开时恢复草稿。

### 4.5 备份记录

`backup_records`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | TEXT PRIMARY KEY | UUID |
| path | TEXT NOT NULL | 备份文件路径 |
| kind | TEXT NOT NULL | `daily` / `before_restore` / `before_migrate` |
| created_at | TEXT NOT NULL | 创建时间 |
| app_version | TEXT NOT NULL | 应用版本 |

备份文件命名：

```text
2notes-YYYYMMDD-HHMMSS-{kind}.sqlite
```

## 5. SQLite 和迁移策略

第一版使用内置迁移表：

`schema_migrations(version INTEGER PRIMARY KEY, applied_at TEXT NOT NULL)`

规则：

- 应用启动时先打开数据目录，再执行迁移。
- 每个迁移必须幂等，不依赖外部状态。
- 迁移失败时应用不进入主界面，提示用户查看日志。
- 版本升级前不自动删除旧数据库文件。

第一版全文搜索使用 SQLite FTS5：

`entries_fts(entry_id, title, original_content, current_content, tags_text)`

更新策略：

- 条目内容、标题、标签变化后同步更新 FTS。
- 搜索范围覆盖标题、当前内容、原始内容、标签名。
- 先做简单关键词搜索，不做复杂查询语言。

## 6. Rust / Tauri 能力边界

### 6.1 Commands

第一版需要的 Tauri commands：

```text
entries_create(content)
entries_list(filter)
entries_get(id)
entries_update(id, patch)
entries_move_to_trash(ids)
entries_restore_from_trash(ids)
entries_delete_forever(id)
entries_batch_update(ids, patch)

tags_suggest(query)
tags_list()

settings_get()
settings_update(patch)
settings_migrate_data_dir(target_dir)

draft_get()
draft_update(content)
draft_clear()

backup_run_now(kind)
backup_list()
backup_restore(backup_id)

export_markdown(target_dir)

window_open_main()
window_open_quick_capture()
app_quit()
```

返回值统一使用结构化错误：

```rust
type AppResult<T> = Result<T, AppError>;
```

错误需要带上下文，底层错误使用 `anyhow` 或自定义错误时必须保留来源。

### 6.2 窗口

第一版至少两个窗口：

- 主窗口：列表、详情、搜索、标签、回收站、设置。
- 快速记录窗口：中央偏上、命令面板形态、提交后关闭。

关闭主窗口时不退出应用，而是隐藏到系统托盘。退出只能通过托盘退出或应用内明确退出动作。

### 6.3 系统托盘

托盘菜单：

- 打开主窗口。
- 快速记录。
- 暂停剪贴板监听。
- 退出应用。

剪贴板项只作为独立能力入口，不与主动条目收集箱耦合。

### 6.4 全局快捷键

默认 `Ctrl + Alt + Space` 呼出快速记录窗口。

规则：

- 快捷键冲突时，设置页需要提示注册失败。
- 用户修改快捷键后，Rust 侧重新注册。
- 注册失败不能影响主窗口打开和已有数据访问。

## 7. 前端设计

### 7.1 主窗口

左侧导航：

- 收集箱
- 搜索 / 全部
- 标签
- 回收站
- 设置

主内容区：

- 列表：默认显示 `pending` 且未删除条目，按 `created_at DESC` 排序。
- 详情面板：编辑标题、当前内容、类型、状态、标签；原始内容默认折叠。

### 7.2 快速记录窗口

行为：

- 打开时加载最后一份草稿。
- 输入变化后 debounce 保存草稿。
- `Enter` 提交并关闭。
- `Shift + Enter` 换行。
- `Esc` 取消并关闭。
- trim 后为空不创建条目。
- 保存失败时窗口不关闭，保留输入，显示失败状态，并允许重试或复制。

提交成功后：

- 创建主动条目。
- 清空草稿。
- 显示极短“已保存”反馈。
- 关闭快速记录窗口。

### 7.3 详情面板

字段：

- 标题：可编辑，不强制填写。
- 当前内容：纯文本编辑，自动保存。
- 原始内容：默认折叠。
- 类型：未澄清、灵感、任务、资料、问题。
- 状态：待处理、已完成、已归档。
- 标签：自由输入，提示已有标签。

自动保存：

- 本地 UI 先保留编辑态。
- debounce 调用 `entries_update`。
- 显示 `保存中 / 已保存 / 保存失败`。
- 保存失败不能回滚用户输入。

### 7.4 搜索和筛选

搜索覆盖：

- 标题。
- 当前内容。
- 原始内容。
- 标签名。

筛选维度：

- 类型。
- 状态。
- 标签。

第一版不做高级查询语言，也不做复杂条件组合编辑器。

### 7.5 回收站

回收站显示 `deleted_at IS NOT NULL` 的主动条目。

支持：

- 恢复。
- 单条永久删除。

第一版不做清空回收站。

### 7.6 设置页

设置项：

- 全局快捷键。
- 开机自启动。
- 数据位置。
- 备份目录。
- 备份保留数量。
- 剪贴板监听开关。
- 导出 Markdown。
- 打开日志目录。

首次启动引导：

1. 选择数据位置。
2. 确认或修改全局快捷键。
3. 选择是否开启开机自启动。

## 8. 自动保存

自动保存分两类：

- 快速记录草稿：保存到 `drafts`，只保留最后一份。
- 条目详情编辑：保存到 `entries.current_content`、`title`、`type`、`status`、标签关系。

失败处理：

- 保留本地编辑态。
- 明确提示失败。
- 允许重试。
- 不静默丢弃。
- 不自动回滚旧值覆盖当前输入。

## 9. 备份、恢复和数据迁移

### 9.1 自动备份

启动时检查最近一次成功备份。

如果距离上次成功备份超过 24 小时：

1. 使用 SQLite backup API 或 `VACUUM INTO` 生成一致性备份。
2. 将备份文件写入备份目录。
3. 写入 `backup_records`，同时允许备份列表通过扫描备份目录重建。
4. 超过保留数量时删除最旧的自动备份。

默认保留最近 10 份，用户可配置。

### 9.2 从备份恢复

恢复流程：

1. 用户选择备份。
2. 应用创建当前库的 `before_restore` 快照。
3. 校验目标备份文件存在且可读。
4. 关闭当前数据库连接。
5. 替换数据库文件。
6. 重新打开数据库并执行完整性检查。
7. 成功后提示恢复完成。

失败处理：

- 保留当前库。
- 不进入半恢复状态。
- 记录本地日志。

### 9.3 数据位置迁移

迁移流程：

1. 用户选择新数据目录。
2. 创建 `before_migrate` 备份。
3. 复制数据库、配置和必要数据文件到新目录。
4. 打开新位置并校验。
5. 成功后更新 bootstrap 配置中的 `data_dir`。

失败处理：

- 继续使用原路径。
- 不删除原数据。
- 记录本地日志。

## 10. Markdown 导出

导出范围：全部主动条目，不包含已永久删除内容。

文件粒度：一条主动条目一个 `.md` 文件。

文件名：

```text
YYYY-MM-DD-HHMMSS-内容摘要.md
```

规则：

- 清理 Windows 非法文件名字符。
- 摘要过长时截断。
- 同名冲突时追加短 ID。

Markdown 结构：

```markdown
---
id: "entry-id"
type: "idea"
status: "pending"
tags:
  - "标签"
created_at: "2026-06-29T10:00:00+08:00"
updated_at: "2026-06-29T10:05:00+08:00"
---

# 标题或内容摘要

当前内容

---

## 原始内容

首次捕获内容
```

第一版不支持 Markdown 反向导入。

## 11. 本地日志和隐私

产品永远不上传用户数据。

第一版只写本地日志，不做远程错误上报、遥测、分析埋点或任何形式的数据上传。

日志记录范围：

- 应用启动和退出。
- 数据库打开和迁移。
- 全局快捷键注册失败。
- 自动保存失败。
- 备份、恢复、数据迁移。
- Markdown 导出。

日志不得主动打印完整条目内容、剪贴板内容或敏感文本。

## 13. 开发任务拆分

第一批：项目骨架

- 初始化 Tauri + Vue 3 + TypeScript。
- 配置 strict TypeScript。
- 建立 Rust command、db、system、files 目录。
- 建立基础窗口和托盘。

第二批：数据层

- SQLite 初始化和迁移表。
- `entries`、`tags`、`entry_tags`、`settings`、`drafts`、`backup_records`。
- FTS5 搜索表。
- Rust repo 层测试。

第三批：主动捕获

- 快速记录窗口。
- 全局快捷键。
- 单份草稿恢复。
- 创建条目。
- 保存失败保护。

第四批：主窗口

- 左侧导航。
- 收集箱列表。
- 详情面板。
- 类型、状态、标签编辑。
- 自动保存和保存状态提示。

第五批：整理能力

- 搜索。
- 类型、状态、标签筛选。
- 批量改状态。
- 批量加 / 移除标签。
- 回收站、恢复、永久删除。

第六批：本地可靠性

- 设置页。
- 数据位置选择和迁移。
- 自动备份。
- 从备份恢复。
- 本地日志。

第七批：导出和安装

- Markdown 全量导出。
- Windows 安装包。
- 最终验收测试。

## 14. 明确不实现

本实现设计不包含：

- AI。
- 知识库链接解析和反向链接。
- 多端同步。
- 云备份实际接入。
- 自动更新。
- 数据库加密和应用锁。
- 附件、图片、截图。
- 富文本编辑器。
- 提醒、日程、截止时间、优先级。
- 协作、账号、登录、权限。
- 标签重命名和合并。
- Markdown 反向导入。
- 远程上报、遥测、数据上传。
