# 2notes 全量优化设计

日期：2026-07-06

## 目标

本轮优化不扩展产品形态，聚焦把第一阶段闭环做稳：数据默认不丢、导出语义清晰、列表性能不随条目数线性恶化、保存失败有可恢复入口、CI 能拦住格式和基础安全问题。

成功标准：

- Markdown 默认只导出未进入回收站的条目。
- 列表页批量加载标签，避免每条记录额外查询一次。
- 自动保存失败时用户能显式重试，切换条目或退出不会静默丢掉本地编辑。
- CI 覆盖格式检查、Rust 格式检查和前端依赖审计；Rust 依赖审计在工具可用时执行。
- 应用提供本地备份目录、手动备份和恢复前快照能力。
- 搜索优先使用 SQLite FTS5；如果运行环境不支持 FTS5，保留现有 LIKE 搜索作为 fallback。

## 方案

### 数据与导出

`EntriesRepo::list_exportable` 改为仅返回 `deleted_at IS NULL` 的条目。回收站数据仍保留在 SQLite，可通过恢复后再次导出。导出文件继续使用临时文件和 `persist_noclobber`，避免覆盖用户已有文件。

### 查询性能

列表查询先取当前页 entry，再用 entry id 集合一次性查询标签并组装到列表项。详情页仍保留单条查询，避免过度抽象。这个改动不改变 command 契约。

### 保存失败恢复

`SaveState` 增加可选重试事件，详情页把 `autosave.retry` 接出来。失败状态只阻止切换/退出，不清空编辑态。快速记录仍保持失败时窗口不隐藏。

### 工程门禁

新增 `.prettierignore` 和 `format:check`，CI 中运行 Prettier check、`cargo fmt --check`、`pnpm audit --prod`。`cargo audit` 不作为硬依赖安装，使用“可用则执行，不可用则提示”的脚本，避免 CI 因缺少子命令直接失效。

### 本地备份

备份目录放在 app data 下的 `backups/`。后端新增备份 command：

- `backups_create(kind)`：创建当前数据库快照。
- `backups_list()`：列出 `.sqlite` 备份文件。
- `backups_restore(path)`：恢复前先创建 `before_restore` 快照，再替换数据库并重新打开连接。

恢复仅接受备份目录下的 `.sqlite` 文件，避免任意路径替换数据库。

### FTS5 搜索

新增迁移创建 `entries_fts` 和触发器。搜索时优先走 FTS5，返回 entry id 后再复用原有过滤逻辑；如果 FTS 查询失败，降级到原 LIKE 查询。迁移要回填既有数据。
