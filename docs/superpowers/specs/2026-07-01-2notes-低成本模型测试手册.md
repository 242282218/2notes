# 2notes 低成本模型测试手册

日期：2026-07-01

## 使用目标

这份文档给能力较弱或上下文较短的模型使用。测试模型不需要“猜”应用行为，只按步骤执行、收集证据、给出通过或失败结论。

核心原则：

- 先看日志、事件、数据库、进程状态，再看截图。
- 构建通过不等于实际使用通过。
- 每个结论必须有命令输出或明确人工观察支撑。
- 遇到未响应、崩溃、保存失败、数据不一致，直接判失败，不用圆场。
- 不要清空真实数据。测试内容必须带 `TEST_` / `CDP_TEST_` 前缀，结束后只清理这些测试数据。

## 测试模型总流程

每轮测试按这个顺序跑：

1. 环境检查
2. 自动门禁
3. release 构建
4. 实际使用自动验收
5. 卡死 / 崩溃日志检查
6. 数据清理
7. 输出测试报告

不要跳步。某一步失败，先记录失败证据，再继续做日志收集；不要直接说“应该是某原因”。

## 0. 环境检查

在仓库根目录执行：

```powershell
git status --short
Get-Process two_notes -ErrorAction SilentlyContinue |
  Format-List Id,ProcessName,Responding,MainWindowTitle,Path,StartTime
Get-Item -LiteralPath package.json,src-tauri\Cargo.toml
```

记录：

- 当前分支和未提交文件。
- 是否已有 `two_notes.exe` 正在运行。
- 若已有进程，记录路径。安装版路径通常是 `D:\Program Files\2notes\two_notes.exe`，仓库版路径通常是 `src-tauri\target\release\two_notes.exe`。

失败判断：

- 不在仓库根目录：停止测试，要求切换目录。
- 同时存在多个 `two_notes.exe`：判环境风险，先记录，再停止多余进程后继续。

停止进程命令：

```powershell
Get-Process two_notes -ErrorAction SilentlyContinue |
  Stop-Process -Force -ErrorAction SilentlyContinue
```

## 1. 自动门禁

按顺序执行：

```powershell
pnpm run lint --fix
pnpm run test:unit
pnpm run build
cargo test --manifest-path src-tauri\Cargo.toml
cargo clippy --manifest-path src-tauri\Cargo.toml --all-targets --all-features -- -D warnings
```

通过标准：

- 每条命令 exit code 为 0。
- `pnpm run test:unit` 显示测试全部 passed。
- `cargo test` 显示 Rust 测试全部 passed。

失败时必须报告：

- 失败命令。
- 最后一段错误输出。
- 是 lint、类型、单测、构建还是 clippy 失败。

禁止：

- 不能只说“跑了一下”。
- 不能把 `warning` 当失败，除非命令 exit code 非 0 或 `-D warnings` 触发失败。

## 2. release 构建

执行：

```powershell
pnpm run tauri:build
```

通过标准：

- 输出包含 `Built application at:`。
- 存在：

```powershell
Get-Item -LiteralPath `
  src-tauri\target\release\two_notes.exe,`
  src-tauri\target\release\bundle\msi\2notes_0.2.0_x64_en-US.msi,`
  src-tauri\target\release\bundle\nsis\2notes_0.2.0_x64-setup.exe
```

失败时记录：

- 是前端 build 失败，还是 Rust release 编译失败，还是 MSI / NSIS 打包失败。

## 3. 实际使用自动验收：快速记录主路径

优先使用脚本：

```powershell
.\scripts\test\2notes-quick-capture-cdp.ps1
```

脚本做的事情：

- 关闭已有 `two_notes.exe`。
- 启动仓库 release exe。
- 打开 WebView2 CDP 调试端口。
- 在主窗口点击“记录”。
- 在快速记录窗口输入 `CDP_TEST_*` 内容。
- 点击“保存”。
- 检查主窗口是否立即显示新记录。
- 检查 SQLite 是否写入一条测试记录。
- 检查草稿是否清空。
- 停止应用。
- 默认清理测试记录。

通过标准：

- 输出包含 `PASS quick_capture_cdp`。
- 输出包含 `MAIN_HAS_NOTE true`。
- 输出包含 `DB_TEST_ROWS` 且只有一条测试记录。
- 输出 `PROCESS responding=True` 或保存后进程仍可响应。

失败时必须贴：

- `PASS` 是否出现。
- `MAIN_HAS_NOTE` 的值。
- `DB_TEST_ROWS` 输出。
- `STDOUT_LOG` 和 `STDERR_LOG` 路径。

保留测试数据用于人工复查：

```powershell
.\scripts\test\2notes-quick-capture-cdp.ps1 -KeepTestData
```

保留后不要忘记清理，见“数据清理”章节。

## 4. 实际使用人工验收

如果测试模型没有可靠 GUI 控制能力，可以让人按以下步骤操作，模型负责收集日志和数据库证据。

测试内容统一用：

```text
TEST_MANUAL_YYYYMMDD_HHMMSS 快速记录人工验收
```

### 4.1 全局快捷键呼出

步骤：

1. 启动 `src-tauri\target\release\two_notes.exe`。
2. 按 `Ctrl + Alt + Space`。
3. 观察是否出现“快速记录”窗口。

通过：

- 快速记录窗口出现。
- 进程没有未响应。

取证命令：

```powershell
Get-Process two_notes -ErrorAction SilentlyContinue |
  Format-List Id,Responding,MainWindowTitle,Path,StartTime
```

失败：

- 快捷键无反应。
- 出现窗口但应用卡死。
- 出现多个窗口但无法输入。

### 4.2 保存快速记录

步骤：

1. 在快速记录窗口输入测试内容。
2. 点击“保存”或按 Enter。
3. 回到主窗口，看列表是否出现该内容。

数据库取证：

```powershell
@'
import os
import sqlite3

db = os.path.expandvars(r"%APPDATA%\com.local.2notes\data\2notes.sqlite")
con = sqlite3.connect(db, timeout=2)
cur = con.cursor()
for row in cur.execute(
    "select id,title,current_content,type,status,deleted_at,created_at from entries order by created_at desc limit 5"
):
    print(row)
for row in cur.execute("select id,content,revision,updated_at from drafts"):
    print("DRAFT", row)
con.close()
'@ | python -
```

通过：

- SQLite 中有测试记录。
- `drafts` 中 `quick_capture` 内容为空。
- 主窗口列表出现测试记录。

失败：

- 数据库有记录但主窗口不显示：主窗口刷新失败。
- 主窗口显示但数据库没有记录：严重一致性问题。
- 草稿未清空：提交后草稿清理失败。

### 4.3 重启持久化

步骤：

1. 关闭应用。
2. 重新启动 release exe。
3. 查看主窗口是否仍能看到测试记录。

通过：

- 重启后记录仍在。

失败：

- 重启后记录丢失。
- 数据库有记录但 UI 不显示。

### 4.4 草稿恢复

步骤：

1. 呼出快速记录。
2. 输入 `TEST_DRAFT_YYYYMMDD_HHMMSS 草稿恢复`。
3. 不保存，直接按 Esc 或点隐藏。
4. 再次呼出快速记录。

通过：

- 文本自动恢复。
- 进程保持响应。

数据库取证：

```powershell
@'
import os
import sqlite3

db = os.path.expandvars(r"%APPDATA%\com.local.2notes\data\2notes.sqlite")
con = sqlite3.connect(db, timeout=2)
cur = con.cursor()
print(list(cur.execute("select id,content,revision,updated_at from drafts")))
con.close()
'@ | python -
```

失败：

- 草稿丢失。
- 草稿保存后快速窗口无法再次打开。

### 4.5 搜索、标签、回收站、导出

这几项可以低频跑，但每次 release 前至少跑一遍。

搜索：

- 搜索测试记录标题片段。
- 搜索正文片段。
- 搜索标签名。

标签：

- 打开记录详情。
- 添加 `test-tag`。
- 切到“标签”视图。
- 点击 `test-tag`，确认记录出现。

回收站：

- 对测试记录点“移到回收站”。
- 切到“回收站”，确认记录出现。
- 点“恢复”，确认回到收集箱。
- 再移到回收站，点“永久删除”，确认数据库删除。

导出：

- 打开“设置”。
- 执行 Markdown 导出到临时目录。
- 确认生成 `.md` 文件，包含 YAML frontmatter 和原始内容。

## 5. 卡死 / 崩溃取证

只要用户说“卡退”“未响应”“点了没反应”，先跑这一节，不要先截图。

### 5.1 当前进程状态

```powershell
Get-Process two_notes -ErrorAction SilentlyContinue |
  Format-List Id,ProcessName,Responding,MainWindowTitle,Path,StartTime,CPU,WorkingSet64
```

判断：

- `Responding=False`：应用正在未响应。
- 查不到进程：可能已崩溃或被 Windows 关闭。
- `MainWindowTitle` 停在“快速记录”：优先怀疑快速窗口路径。

### 5.2 Windows 应用事件

```powershell
Get-WinEvent -FilterHashtable @{
  LogName='Application'
  StartTime=(Get-Date).AddHours(-3)
} -ErrorAction SilentlyContinue |
  Where-Object {
    $_.ProviderName -match 'Application Error|Windows Error Reporting|Application Hang' -or
    $_.Message -match 'two_notes|2notes|com.local.2notes'
  } |
  Select-Object TimeCreated,Id,ProviderName,LevelDisplayName,Message |
  Format-List
```

必须记录：

- 事件时间。
- Event ID。
- ProviderName。
- Message 中的 exe 路径。

结论规则：

- Event ID `1002` + `Application Hang`：未响应。
- `Application Error`：崩溃，继续找 faulting module。
- 只有 MSIInstaller：只是安装记录，不算运行失败。

### 5.3 WER 报告

```powershell
Get-ChildItem -Path `
  "$env:ProgramData\Microsoft\Windows\WER\ReportArchive",`
  "$env:ProgramData\Microsoft\Windows\WER\ReportQueue" `
  -Recurse -ErrorAction SilentlyContinue |
  Where-Object { $_.FullName -match 'two_notes|2notes' -or $_.Name -match 'two_notes|2notes' } |
  Sort-Object LastWriteTime -Descending |
  Select-Object FullName,Length,LastWriteTime |
  Format-List
```

读取最近的 `Report.wer`：

```powershell
Get-Content -LiteralPath "<Report.wer 路径>" | Select-Object -First 120
```

必须摘录：

- `EventType`
- `AppPath`
- `Sig[3].Value`
- `Sig[4].Value`
- `FriendlyEventName`

### 5.4 未响应时抓 dump

如果进程还在且 `Responding=False`，立即抓 dump：

```powershell
$p = Get-Process two_notes -ErrorAction Stop | Select-Object -First 1
$dump = "D:\PROJECT_ZZZZZZZZZ\2notes\tmp-two-notes-hang-$($p.Id).dmp"
rundll32.exe C:\Windows\System32\comsvcs.dll, MiniDump $p.Id $dump full
Write-Output $dump
```

注意：

- dump 文件可能很大，不要提交到 git。
- 测试报告只写 dump 路径和大小。

## 6. 数据清理

只删除测试前缀数据：

```powershell
@'
import os
import sqlite3

db = os.path.expandvars(r"%APPDATA%\com.local.2notes\data\2notes.sqlite")
con = sqlite3.connect(db, timeout=2)
cur = con.cursor()
for prefix in ["TEST_", "CDP_TEST_"]:
    cur.execute("delete from entries where current_content like ?", (prefix + "%",))
    cur.execute("delete from drafts where id = 'quick_capture' and content like ?", (prefix + "%",))
con.commit()
print("remaining", list(cur.execute(
    "select id,current_content from entries where current_content like 'TEST_%' or current_content like 'CDP_TEST_%'"
)))
print("entry_count", list(cur.execute("select count(*) from entries"))[0][0])
con.close()
'@ | python -
```

禁止：

- 不要删除整个 `com.local.2notes` 目录。
- 不要清空 `entries` 表。
- 不要删除用户真实记录。

## 7. 测试报告模板

每次测试结束输出这个格式：

```markdown

测试对象：仓库 release / 安装版 / dev
exe 路径：
git 状态：

### 结论

- 总结：通过 / 失败
- 阻断问题：
- 非阻断问题：

### 自动门禁

| 项目 | 命令 | 结果 |
| --- | --- | --- |
| lint | `pnpm run lint --fix` | 通过 / 失败 |
| unit | `pnpm run test:unit` | 通过 / 失败 |
| build | `pnpm run build` | 通过 / 失败 |
| cargo test | `cargo test --manifest-path src-tauri\Cargo.toml` | 通过 / 失败 |

| 场景 | 结果 | 证据 |
| --- | --- | --- |

| 重启持久化 | 通过 / 失败 / 未测 | 证据 |

### 卡死 / 崩溃检查

- 当前进程：

- 临时文件是否清理：是 / 否
```

## 8. 便宜模型常见误判

不要犯这些错：

- 看到 `pnpm run build` 通过就说实际使用通过。
- 只看截图，不查 Windows 事件日志。
- 数据库有记录但 UI 没刷新，还说保存通过。
- 应用卡死后只说“可能是电脑问题”。
- 不记录 exe 路径，导致安装版和仓库版混在一起。
- 测试失败后直接修代码，却没留下复现证据。
- 清理测试数据时误删用户真实数据。

## 9. 最小通过标准

一次可以接受的“低成本模型测试”至少要有：

- 自动门禁全部通过。
- `pnpm run tauri:build` 通过。
- `.\scripts\test\2notes-quick-capture-cdp.ps1` 输出 `PASS quick_capture_cdp`。
- Windows 事件日志中没有本轮新增 `Application Hang` 或 `Application Error`。
- 测试记录已清理。

如果少了任意一项，只能说“部分验证通过”，不能说“验收通过”。
