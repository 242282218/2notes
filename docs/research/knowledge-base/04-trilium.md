# Trilium Notes — 详细介绍

> 调研日期：2026-06-27

---

## 1. 设计哲学

Trilium Notes 的设计哲学非常明确：**构建一个可以扩展到 10 万+ 笔记规模的个人知识库**。

它不满足于做一个"不错的笔记应用"，而是要解决一个更难的问题：**当你的笔记数量从几十条增长到几万条时，如何依然保持可管理、可搜索、可关联？**

这个目标决定了 Trilium 的所有设计决策都偏向"结构化"和"可编程"，而不是"自由发挥"。

---

## 2. 核心设计思路

### 2.1 笔记树 + 多父节点（Cloning）

Trilium 的组织方式有两个层次：

**第一层：严格的笔记树**
- 所有笔记组织成一棵深度不限的树。
- 每篇笔记有且只有一个父节点（parent）。
- 树的结构决定了笔记的"主要位置"。

**第二层：克隆（Cloning）——打破树的限制**
- 同一篇笔记可以被"克隆"到树的其他位置。
- 克隆不是复制：克隆和原文共享内容，修改一处，所有克隆都更新。
- 克隆只影响组织结构，不影响内容。

**为什么克隆比复制好？**

1. **同一内容可以从多个角度组织**：一篇关于"机器学习"的笔记可以同时出现在"AI 学习路径"和"技术栈规划"两个分支下。
2. **不会产生物理冗余**：克隆不创建新文件，只是创建新的指针。
3. **结构变化不影响内容**：你可以随时调整笔记在树中的位置，内容不变。

**对 2notes 的启示**：2notes 的条目目前通过标签和类型来组织，如果未来引入"多位置归属"能力（一个条目可以同时属于多个主题），可以参考 Trilium 的克隆设计。

### 2.2 属性驱动的组织和查询

Trilium 的每篇笔记都有一组**属性（Attributes）**：

- 标签（Tags）
- 自定义字段（Custom Fields）
- 关系（Relations）：笔记之间的关系可以标注类型（如"引用自"、"关于"、"依赖于"）
- 优先级、状态等

更重要的是，Trilium 提供了**基于属性的搜索和脚本能力**：

- 可以编写脚本，根据属性自动组织笔记。
- 可以设置规则，新笔记自动打上特定标签。
- 可以创建"脚本笔记"，定期执行自动化任务。

### 2.3 丰富的内容类型和可视化

Trilium 支持的内容类型远超一般笔记应用：

- 纯文本 / Markdown / HTML
- 代码块（支持语法高亮，70+ 种语言）
- 画布（Canvas）：类似 Excalidraw 的自由绘图
- 思维导图
- 关系图谱（Relation Map）：展示笔记之间的关系网络
- 链接图谱（Link Map）：展示笔记之间的引用关系
- 电子表格
- 地图（嵌入 OpenStreetMap）

其中**关系图谱**是一个很有特色的设计：它不是简单地展示"哪些笔记互相链接"，而是展示"笔记之间的关系类型"。你可以看到"A 依赖于 B"、"C 引用了 A"这样的语义化关系。

### 2.4 按笔记粒度的加密

Trilium 允许对**单篇笔记**进行加密：

- 你可以把整个笔记树设为公开，但其中某一篇笔记加密。
- 也可以反过来，大部分笔记加密，只有少数公开。
- 加密密钥存储在本地，服务器端无法解密。

这个设计适合"混合敏感度"的场景：大部分笔记是普通的，但有些包含敏感信息。

### 2.5 自托管同步服务器

Trilium 提供一个同步服务器（Sync Server），可以部署在自己的机器上：

- 客户端之间通过同步服务器交换数据。
- 同步服务器不持有解密密钥，无法读取用户数据。
- 支持多设备同步（桌面端 + 移动端）。

---

## 3. 优点

1. **可扩展性极强**：官方声称可以管理 10 万+ 笔记，实际用户中有管理数万元素的案例。
2. **多父节点（克隆）是真正的差异化功能**：其他笔记应用几乎没有这个能力。
3. **属性驱动的自动化**：脚本和规则系统让笔记管理可以半自动化。
4. **可视化能力丰富**：关系图谱、链接图谱、思维导图、画布都在一个应用里。
5. **按笔记粒度加密**：细粒度的隐私控制。
6. **版本历史**：每篇笔记的每次修改都有记录，可以随时回滚。

---

## 4. 独特之处

### 4.1 笔记即图节点

Trilium 从根本上把笔记看作**图结构中的节点**，而不是文件夹中的文件：

- 树形结构只是"主要位置"，笔记的真正组织方式是图。
- 克隆功能让一个节点可以有多个父位置。
- 关系让节点之间的连接有了语义。
- 图谱可视化让图结构变得可见。

这种设计在开源笔记应用中是最激进的之一。

### 4.2 脚本和自动化

Trilium 提供了一个基于 JavaScript 的脚本系统：

- 可以编写脚本自动处理笔记（批量打标签、移动位置、生成摘要等）。
- 脚本可以定时触发，也可以由事件触发（新建笔记时自动执行）。
- 脚本可以访问 Trilium 的 API，操作任何笔记和属性。

这让 Trilium 不仅仅是一个笔记应用，更像一个**可编程的知识管理系统**。

### 4.3 服务端架构

Trilium 采用客户端-服务端架构（而不是纯本地应用）：

- 后端用 Node.js 运行，管理数据库。
- 前端用 Electron 打包，通过 API 与后端通信。
- 这种架构让同步和多设备支持更容易实现，但也增加了部署复杂度。

## 5. 值得借鉴的设计决策

| 决策 | 具体内容 | 对 2notes 的参考价值 |
|------|---------|-------------------|
| 克隆（多父节点） | 同一笔记可在多处呈现 | 2notes 条目多角度归类可参考 |
| 属性驱动 | 标签、字段、关系、优先级 | 2notes 条目属性系统可扩展 |
| 关系图谱 | 语义化的笔记关系可视化 | 长期可考虑 |
| 脚本自动化 | 基于 JS 的笔记处理脚本 | 2notes AI 整理前可先有规则自动化 |
| 按笔记加密 | 细粒度隐私控制 | 2notes 剪贴板隐私风险可参考此思路 |
| 版本历史 | 每次修改可回滚 | 2notes 条目编辑历史可借鉴 |

---

## 6. 需要注意的教训

1. **UI 不够现代化**：Trilium 的界面设计偏实用主义，美观度不如 Obsidian 和思源笔记。
2. **学习曲线陡峭**：树 + 克隆 + 属性 + 脚本 + 图谱，概念太多，新用户需要较长时间上手。
3. **服务端运维成本**：自托管同步服务器需要一定的运维能力。
4. **移动端体验较弱**：虽然有移动端应用，但功能远不如桌面端完整。
5. **社区较小**：相比 Obsidian 和 Joplin，Trilium 的社区规模和活跃度有限。
