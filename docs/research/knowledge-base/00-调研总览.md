## 二、设计理念分类

根据核心设计哲学，可将上述项目分为四类：

### A. 纯文本/开放格式派
> 数据主权第一，格式自由是底线

- **Obsidian** — Markdown 纯文本 + 最大社区生态
- **QOwnNotes** — C++ 原生 + Nextcloud 生态 + MCP 服务器
- **Zettlr** — Markdown + 学术出版管线
- **Foam** — VS Code 扩展 + 开发者知识管理

**共性**：所有笔记以纯文本文件存储，不绑定任何特定应用，换工具零成本。

### B. 图谱/双向链接派
> 知识不是文件夹，是网络

- **Obsidian** — 双向链接 + 图谱视图 + 常青笔记方法论
- **Logseq** — 大纲 + 双向链接 + 融合 Roam/Org/TiddlyWiki/Workflowy 四种范式
- **Trilium Notes** — 层次树 + 多父节点 + 关系图谱可视化
- **SiYuan Note** — 块级引用 + 双向链接

**共性**：打破传统文件夹层级，用链接构建知识网络。

### C. 本地优先/隐私派
> 你的数据，你完全掌控

- **Joplin** — 端到端加密 + EU 法规合规 + CLI 终端
- **Anytype** — P2P 去中心化同步 + 零知识加密
- **AppFlowy** — 自托管 + 数据主权 + 可自定义 OS
- **AFFiNE** — 本地优先 + 隐私优先 + 开源可定制

**共性**：数据存在本地，不依赖中央服务器，强调用户自主权。

### D. 功能融合/创新派
> 不止于笔记，扩展边界

- **RemNote** — 笔记 + 闪卡 + SRS 间隔重复，一体化学习
- **SiYuan Note** — 笔记 + 数据库 + SQL 查询 + 闪卡复习
- **AFFiNE** — 文档 + 白板 + 画布，超融合工作空间
- **Outline** — 团队文档 + 白标 + Slack 集成

**共性**：在笔记基础上叠加其他能力，创造复合价值。

## 三、与 2notes 的关联分析

2notes 的产品路线是：**快速捕获系统 → 整理系统 → 本地知识库**。

知识库阶段需要借鉴的关键设计思路：

### 可直接参考的
| 来源 | 设计思路 | 与 2notes 的关联 |
|------|---------|----------------|
| Obsidian | 常青笔记方法论（持续修订、连接已有知识） | 2notes 条目从"待澄清"到"沉淀"的流转天然契合 |
| Logseq | 大纲式结构化表达 | 适合 2notes 条目的层次化整理 |
| Trilium Notes | 多父节点（同一内容可出现在多个位置） | 2notes 条目分类/标签后可被多角度检索 |
| SiYuan Note | 块级引用 | 2notes 长期可考虑条目内子块的链接能力 |
| Foam | 知识健康检查（孤儿笔记、链接诊断） | 2notes 可借鉴"待处理内容发现"的理念 |
| QOwnNotes | MCP 服务器（AI Agent 直接访问笔记） | 与 2notes AI 整理权限边界设计高度相关 |

### 需要谨慎对待的
| 来源 | 设计思路 | 注意事项 |
|------|---------|---------|
| Obsidian | 图谱可视化 | 2notes 第一阶段明确不做 |
| AFFiNE | Canvas/白板 | 2notes 第一阶段明确不做 |
| RemNote | SRS 间隔重复 | 超出 2notes 范围，偏学习工具 |
| Outline | 团队协作 | 2notes 明确不做多人协作 |
| AppFlowy | 工作场所 OS | 定位过重，不适合个人收集系统 |

### 核心理念对齐
- **Obsidian 的"数据主权"** — 2notes 个人单机定位完全一致
- **Logseq 的"隐私优先"** — 2notes 剪贴板流水的隐私风险需要同等重视
- **Foam 的"原子化笔记"** — 2notes 最小信息单位"条目/卡片"理念相同
- **Joplin 的"开放格式"** — 2notes 长期数据可移植性需要考虑

## 四、调研结论

1. **知识库方向的核心竞争维度**：数据格式开放性、链接方式（页面级 vs 块级）、组织方式（文件夹 vs 标签 vs 图谱）、生态扩展性。

2. **2notes 的优势切入点**：从"快速捕获"自然过渡到知识库，已有"收集箱→澄清→沉淀"的内容流转设计，这与 Obsidian 常青笔记方法论高度契合。

3. **需要避免的陷阱**：不要一开始就做图谱可视化、Canvas、协作等重功能；保持纯文本/开放格式的长期承诺。

4. **下一步建议**：针对 Obsidian、Logseq、SiYuan Note、Trilium Notes 这四个与 2notes 知识库方向最相关的项目，进行更深入的单项目设计思路拆解。
