# Zettlr — 详细介绍

> 调研日期：2026-06-27

---

## 1. 设计哲学

Zettlr 的设计哲学可以用它的口号概括：**"Publish, not perish"（出版而非消亡）。**

Zettlr 的核心理念是：**笔记的最终目的不是"存起来"，而是"发出去"。**

它瞄准的是一个被其他笔记应用忽视的群体：**学术研究者、学生、写作者**——这些人写笔记不是为了个人知识管理，而是为了写论文、写书、写文章。笔记是他们出版流程中的一个环节，不是终点。

---

## 2. 核心设计思路

### 2.1 出版管线（Publication Pipeline）

Zettlr 最核心的设计是**从笔记到出版的完整管线**：

1. **写笔记**：在 Zettlr 中用 Markdown 写笔记。
2. **组织笔记**：用标签、链接、Zettelkasten 方法组织笔记结构。
3. **组装稿件**：从笔记中选择相关的内容，组装成一篇稿件。
4. **导出发表**：一键导出为 PDF、Word、LaTeX、HTML 等各种出版格式。

这个管线的关键是：**每一步都是连贯的，不需要跳出 Zettlr 或用其他工具做中间转换。**

### 2.2 Pandoc 集成

Zettlr 内置了 **Pandoc**（著名的文档转换工具）：

- 支持导出为 Word (.docx)、LaTeX (.tex)、PDF、HTML、EPUB、Markdown 等多种格式。
- 支持自定义导出模板（pandoc template）。
- 可以在导出时指定引用样式（APA、MLA、Chicago 等）。

**为什么 Pandoc 集成重要？**

因为学术出版格式多样，没有一种格式通吃。Pandoc 是目前最强大的通用文档转换工具，Zettlr 集成 Pandoc 等于继承了它的**所有导出能力**。

### 2.3 引用管理器集成

Zettlr 支持与 **Zotero** 和 **JabRef** 两款引用管理器的集成：

- 在笔记中直接插入引用（citation）。
- 引用格式自动匹配目标出版格式。
- Zotero 库中的文献可以直接在 Zettlr 中搜索和引用。

这个设计解决了学术写作中"笔记"和"参考文献"脱节的问题——你可以在写笔记的同时管理引用，不需要在笔记应用和文献管理工具之间切换。

### 2.4 Zettelkasten 方法内置支持

Zettlr 内置了对 **Zettelkasten（卡片盒笔记法）** 的支持：

- 自动为每条笔记生成唯一 ID（时间戳 + 随机字符）。
- 支持笔记间的链接和分组。
- 提供 Zettelkasten 专用的文件夹结构和命名约定。
- 可以自动生成笔记的索引页。

Zettlr 是少数在产品设计之初就考虑 Zettelkasten 方法的笔记应用之一，而不是事后添加的插件功能。

### 2.5 片段自动化（Snippets）

Zettlr 的 Snippets 功能类似于模板，但更灵活：

- 可以定义常用的文本片段（如"引用格式"、"章节标题"）。
- 通过快捷键或自动补全插入。
- 支持变量替换（如当前日期、作者名等）。

这个功能对经常写固定格式内容的用户很有价值。

## 3. 优点

1. **学术出版导向**：从笔记到出版的完整管线，适合写论文和写书。
2. **Pandoc 集成**：导出格式丰富，自定义能力强。
3. **引用管理集成**：Zotero/JabRef 无缝对接。
4. **Zettelkasten 内置**：不需要额外配置或插件。
5. **完全免费开源**：GPL-3.0 协议，无付费墙。
6. **跨平台**：Windows、macOS、Linux。

---

## 4. 独特之处

### 4.1 笔记 + 出版的完整管线

Zettlr 是**唯一一个把"出版"作为核心设计目标的开源笔记应用**：

- Obsidian 关注的是"思考和连接"。
- Logseq 关注的是"大纲和复习"。
- Joplin 关注的是"隐私和自由"。
- **Zettlr 关注的是"写和发"。**

这个定位让它避开了与其他笔记应用的正面竞争，在学术写作这个细分领域中几乎没有直接对手。

### 4.2 面向学校和机构

Zettlr 的设计考虑了学术机构和学校的实际需求：

- 支持学校定制的引用样式。
- 支持 LaTeX 模板（学术论文常用格式）。
- 支持批量导出（一篇论文可能引用几十条笔记）。
- 价格免费（对学生和教师零成本）。

### 4.3 纯 Markdown + 增强语法

Zettlr 使用标准 Markdown 作为基础格式，但扩展了一些学术写作需要的语法：

- 内联引用：`@authorYear` 格式的引用标记。
- 脚注和尾注。
- 交叉引用（引用文档中的其他部分）。
- 自定义 CSS 主题。

## 6. 需要注意的教训

1. **受众窄**：学术出版导向意味着对非学术用户的需求照顾不足。
2. **UI 不够现代**：界面设计偏功能主义，美观度不如 Obsidian。
3. **移动端缺失**：没有官方移动端应用。
4. **学习 Pandoc 模板有门槛**：自定义导出格式需要懂 Pandoc 的模板语法。
5. **社区较小**：用户基数不大，社区讨论和插件资源有限。
