# SiYuan Note（思源笔记）— 详细介绍

> 调研日期：2026-06-27

---

## 1. 设计哲学

思源笔记的核心理念是 **"Refactor your thinking"（重构思维）**。

它的出发点是：传统的笔记应用把"文档"当作最小单位，但人的思维不是按文档组织的。我们想到的是**一个个片段、一段段关系、一层层结构**。思源笔记试图通过**块级粒度**来还原这种思维方式。

同时，思源笔记强调**隐私优先、数据本地化**，所有数据默认存储在本地，不强制联网。

---

## 2. 核心设计思路

### 2.1 块级引用（Block-level Reference）

这是思源笔记最核心的差异化设计：

- **Obsidian 和大多数笔记工具**：链接的单位是"整篇文档"。你只能链接到一篇笔记的标题。
- **思源笔记**：链接的单位是"块（Block）"。每个段落、每个列表项、每个嵌入块都是一个独立的块，有唯一的 ID。你可以精确链接到某篇笔记中的某一个段落。

**块级引用的设计价值**：

1. **知识组装更精细**：你可以把多篇笔记中的相关片段组装到一起，形成新的内容。就像乐高积木，每块积木是一个知识片段。
2. **反向追踪更精准**：不仅知道"哪篇笔记引用了我"，还知道"哪个段落引用了我"。
3. **内容复用更方便**：同一个块可以在多处被引用，修改一处，引用处自动更新。

### 2.2 所见即所得的 Markdown 编辑器

思源笔记的编辑器设计有几个特点：

- **底层是 Markdown，上层是 WYSIWYG**：用户看到的是富文本界面（加粗、标题、列表等直接可见），但保存的格式仍然是标准 Markdown。
- **块级操作**：每个块可以独立拖拽、折叠、移动、引用。不像传统编辑器那样只能操作整段文字。
- **嵌入式块**：一个块可以嵌入另一个块的内容，形成"内容即链接"的效果。

### 2.3 内置数据库能力

思源笔记在笔记应用中罕见地内置了数据库能力：

- **表格视图**：可以将一组笔记以表格形式展示，每列是一个属性（标签、日期、自定义字段等）。
- **SQL 查询嵌入**：在笔记中嵌入 SQL 查询语句，动态获取符合条件的笔记内容并展示。
- **闪卡间隔重复**：内置类似 Anki 的复习功能，可以基于笔记内容生成闪卡。

这个设计让思源笔记不仅仅是"笔记应用"，更像是一个**轻量级的个人数据管理系统**。

### 2.4 丰富的内容类型

思源笔记支持的內容类型远超一般笔记应用：

- 数学公式（KaTeX）
- 图表（Mermaid）
- 甘特图
- 五线谱（ABC Notation）
- PDF 标注
- 代码块（多语言高亮）
- 嵌入网页

特别是**五线谱支持**，在笔记应用中几乎是独一无二的。

### 2.5 一键多平台发布

思源笔记提供了一个实用但很少被其他开源项目关注的功能：**一键导出到多个内容平台**。

- 支持导出到微信公众号、知乎、语雀、CSDN 等国内平台。
- 导出时自动处理格式转换，尽量保持原样。

这个设计反映了思源笔记对中国用户实际需求的理解——笔记不仅是个人知识管理，也是内容创作的起点。

## 3. 优点

1. **块级引用是真正的差异化优势**：在开源笔记应用中，思源是块级引用的先行者。
2. **开源免费商用**：Apache-2.0 协议，商业使用零成本。
3. **百万字级文档流畅编辑**：性能优化做得很好，大文档不卡顿。
4. **全平台覆盖**：Windows、macOS、Linux、Android、iOS、鸿蒙（HarmonyOS）。
5. **中文原生支持**：从设计之初就考虑中文用户的习惯和需求。
6. **插件市场和模板系统**：有官方的插件分发平台和模板库。

---

## 4. 独特之处

### 4.1 块级引用 + SQL 查询的组合

思源笔记把"精确到段的链接"和"数据库查询"结合在一起，创造了一种新的知识组织方式：

- 你可以写一条笔记，里面嵌入一个 SQL 查询，自动展示所有包含某个标签的最新笔记。
- 你可以链接到另一篇笔记中的某一个具体段落，而不是整篇。
- 这让你既能做精细的知识组装，又能做动态的知识聚合。

### 4.2 面向中国市场的独特设计

思源笔记在很多细节上体现了对中国用户需求的理解：

- **鸿蒙系统支持**：在国产操作系统上的适配是其他国际项目不具备的。
- **一键多平台发布**：国内内容平台的导出能力。
- **中文搜索优化**：对中文分词和搜索的处理更好。
- **本地化社区**：有活跃的中文社区和文档。

### 4.3 本地 JSON 存储

思源笔记不使用 Markdown 文件存储，而是使用**本地的 JSON 格式**。

- 优点：结构化程度更高，支持块级 ID、属性、关系等复杂结构。
- 缺点：数据不直接可读，必须用思源笔记打开。

这个选择在"结构化能力"和"格式开放性"之间做了不同的权衡。

## 5. 值得借鉴的设计决策

| 决策 | 具体内容 | 对 2notes 的参考价值 |
|------|---------|-------------------|
| 块级引用 | 精确链接到段落级别 | 长期知识库阶段可考虑 |
| SQL 查询嵌入 | 动态聚合符合条件的笔记 | 2notes 沉淀后可借鉴 |
| 表格视图 | 笔记以表格形式展示 | 2notes 整理视图可参考 |
| 闪卡复习 | 内置间隔重复 | 与 Logseq 思路一致 |
| 嵌入式块 | 内容即链接，引用即展示 | 长期可参考 |
| WYSIWYG + Markdown | 富文本编辑 + 纯文本存储 | 编辑体验可参考 |

## 6. 需要注意的教训

1. **JSON 存储降低了格式开放性**：用户无法直接用其他工具查看和编辑数据，换工具成本高于 Markdown 方案。
2. **功能多但学习成本也高**：块引用、SQL、表格、闪卡……功能越多，新用户需要理解的概念越多。
3. **跨平台同步方案不够成熟**：虽然有同步功能，但相比 Obsidian Sync 和 Joplin Cloud，体验还有差距。
4. **插件生态尚在建设中**：虽然有插件市场，但质量和数量都不如 Obsidian 社区。
