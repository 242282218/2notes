# Joplin — 详细介绍

> 调研日期：2026-06-27

---

## 1. 设计哲学

Joplin 的设计哲学可以浓缩为一句话：**"Free your notes"（解放你的笔记）。**

这个"自由"包含三层含义：

1. **格式自由**：你的笔记不是专有格式，随时可以带走。
2. **同步自由**：你可以选择任何云服务商做同步，不被绑定到单一平台。
3. **代码自由**：AGPL-3.0 开源协议，任何人可以审查、修改、分发代码。

Joplin 的创始人是法国开发者 Laurent Cozic，他做 Joplin 的动机很直接：**他发现自己在用的笔记应用不尊重用户的数据主权，于是决定自己做一款真正自由的笔记应用。**

---

## 2. 核心设计思路

### 2.1 端到端加密（E2EE）

Joplin 的端到端加密设计有一个重要特点：**加密发生在客户端，服务器端完全不知道内容。**

- 用户在 Joplin 中设置的加密密钥永远不会离开用户的设备。
- 即使同步后端是 Joplin 自己的云服务（Joplin Cloud），服务器也无法读取用户笔记。
- 加密算法使用业界标准的 AES-256-GCM。

**为什么这个设计重要？**

Joplin 的定位是"隐私优先的笔记应用"，而端到端加密是隐私保护的最后一道防线。即使同步服务被攻破、被政府要求提供数据、或被内部员工滥用，用户的笔记内容也不会泄露。

### 2.2 多后端同步

Joplin 不绑定任何特定的同步服务，而是支持多种同步后端：

- Joplin Cloud（官方云服务）
- Dropbox
- OneDrive
- WebDAV（兼容 Nextcloud、Seafile 等）
- S3（AWS S3、MinIO 等）
- 文件系统（局域网共享文件夹）

这个设计的核心理念是：**同步是基础设施，不应该成为锁定用户的理由。** 用户可以自由选择最适合自己的同步方案。

### 2.3 开放格式存储

Joplin 的本地数据存储使用 **SQLite 数据库**，但笔记内容本身是标准的 Markdown 格式：

- 笔记内容：Markdown 文本。
- 附件：原样存储（图片、PDF、音频等）。
- 元数据：标题、标签、创建时间等存储在 SQLite 中。

更重要的是，Joplin 提供了**导出功能**，可以将所有笔记导出为单一 `.jwl` 文件（压缩的 JSON 格式）或单独的 Markdown 文件。这意味着即使有一天不用 Joplin，数据也能完整带走。

### 2.4 Web Clipper（网页剪藏）

Joplin 的网页剪藏扩展是一个功能完整且设计合理的工具：

- 支持保存完整页面、简化版、截图三种模式。
- 剪藏时自动提取文章标题、作者、发布日期等元数据。
- 剪藏内容自动进入指定的笔记本。
- 支持正则表达式规则，自动给剪藏内容打标签。

**设计亮点**：剪藏不是"存下来完事"，而是可以和笔记本、标签系统联动，让剪藏内容进入后续的处理流程。

### 2.5 命令行终端应用（CLI）

Joplin 提供了一个完整的命令行工具 `joplin`：

- 可以在终端中创建、编辑、搜索、导出笔记。
- 可以脚本化操作（批量重命名、批量打标签等）。
- 支持远程操作（通过 Joplin Server）。

这个设计满足了**开发者用户**的需求——他们希望在终端工作流中也能管理笔记，而不必切换到 GUI 应用。

## 3. 优点

1. **真正的开源**：AGPL-3.0 协议，代码、服务器、移动端全部开源。
2. **隐私保护到位**：端到端加密 + EU 法规合规，适合对隐私有高要求的用户。
3. **多格式支持**：图片、视频、PDF、音频、数学公式、手绘板输入，内容类型丰富。
4. **多平台覆盖**：Windows、macOS、Linux、Android、iOS、Web、CLI。
5. **插件系统**：支持安装社区插件扩展功能。
6. **免费使用**：核心功能全部免费，没有付费墙。

## 4. 独特之处

### 4.1 "法国替代方案"定位

Joplin 有一个明确的市场定位：**作为法国/EU 地区的 Notion/Obsidian/OneNote 替代方案**。

这个定位带来了几个设计特点：

- **GDPR 合规**：Joplin 的设计考虑了欧盟 GDPR 的要求，数据存储在欧盟境内是可行的。
- **公共部门采用**：Joplin 被法国政府部门采用，作为公务员的笔记工具。这在开源笔记应用中是罕见的。
- **法语社区活跃**：有完善的法语文档和社区支持。

### 4.2 笔记笔记本 + 标签双层组织

Joplin 采用传统的"笔记本 + 标签"双层组织方式：

- 笔记本是树状结构，可以嵌套。
- 标签是扁平结构，一个笔记可以有多个标签。
- 笔记本和标签正交：一个笔记属于一个笔记本，但可以有多个标签。

这种设计比纯文件夹方式灵活，又比纯标签方式有结构感。对于"不想学复杂方法论但需要一定组织能力"的用户来说，这是一个合理的平衡点。

### 4.3 扩展 API

Joplin 提供了完整的扩展 API，开发者可以：

- 创建新的笔记类型（如自定义卡片模板）。
- 添加新的导入/导出格式。
- 修改编辑器行为。
- 集成外部服务。

扩展使用 JavaScript/TypeScript 编写，打包为 `.jex` 文件安装。

## 6. 需要注意的教训

1. **UI 不够精致**：Electron 应用的界面设计偏功能主义，美观度和交互流畅度不如 Obsidian。
2. **同步稳定性问题**：多后端同步意味着要维护多种同步协议的兼容性，偶尔会出现同步冲突。
3. **移动端体验一般**：移动端功能相对桌面端有缩水，尤其是编辑能力。
4. **双向链接支持较晚**：Joplin 直到 2.6 版本才加入双向链接，起步晚于 Obsidian 和 Logseq。
5. **学习材料分散**：文档和社区讨论比较分散，新用户找到系统性学习路径不容易。
