# Anytype — 详细介绍

> 调研日期：2026-06-27

---

## 1. 设计哲学

Anytype 的设计哲学是：**"Your Digital Brain"（你的数字大脑）。**

它不把自己定位为"笔记应用"，而是定位为**个人知识操作系统（Knowledge OS）**。核心理念是：

1. **本地优先（Local-first）**：所有数据默认存储在本地设备上。
2. **去中心化（Decentralized）**：设备之间通过 P2P 同步，不依赖中央服务器。
3. **可组合性（Composable）**：用户不是被动使用预设的内容类型，而是可以自由定义自己的数据模型。

Anytype 认为，每个人的知识结构和信息需求都是独特的，**工具应该适应用户，而不是让用户适应工具**。

---

## 2. 核心设计思路

### 2.1 对象类型系统（Object Types）

这是 Anytype 最核心的设计创新：

- **一切皆对象（Everything is an Object）**：笔记、任务、联系人、项目、文件……所有信息都是"对象"。
- **每个对象有类型**：类型定义了对象的属性和行为。比如"笔记"类型有"标题""内容""标签"属性，"任务"类型有"状态""截止日期"属性。
- **用户可以自定义类型**：不只是预设几种类型，用户可以创建全新的类型（如"书籍""菜谱""代码片段"），并为每种类型定义自己的属性。

**这个设计的价值**：

1. **灵活性远超传统笔记**：Notion 的"数据库"概念已经很灵活，但 Anytype 让用户可以自定义类型本身，而不仅仅是字段。
2. **结构化 + 自由度的平衡**：类型提供了结构，但结构由用户定义，不是工具强加的。
3. **查询和过滤天然支持**：因为对象有明确的类型和属性，所以可以按类型、属性值进行搜索和过滤。

### 2.2 P2P 去中心化同步

Anytype 的同步方案不依赖任何中央服务器：

- **设备直连同步**：你的设备之间通过 P2P 协议直接交换数据。
- **Protocol Buffers + Libp2p**：使用标准化的序列化协议和 P2P 网络库。
- **零知识加密**：同步过程中的数据是加密的，任何中间节点（包括 Anytype 自己的服务器）都无法读取。
- **断网可用**：即使完全离线，应用也完全可用。

**为什么 P2P 同步有意义？**

1. **没有单点故障**：不依赖任何中央服务器，服务不会因服务器宕机而中断。
2. **隐私更强**：数据不经中央服务器中转，减少了泄露风险。
3. **延迟更低**：设备直连同步，不绕道云端。

### 2.3 可组合的块结构

Anytype 的内容编辑基于"块（Block）"：

- 每个块是一种类型的对象（文本块、图片块、数据库块、看板块、日历块……）。
- 块可以自由组合，形成复杂的页面结构。
- 块之间可以相互链接和引用。
- 块的内容可以跨页面复用（类似思源笔记的块引用）。

### 2.4 工作空间（Workspace）概念

Anytype 用"工作空间"来组织用户的数据：

- 一个工作空间是一个独立的对象集合，有自己的一套对象类型和布局。
- 用户可以创建多个工作空间，每个工作空间对应一个生活或工作领域。
- 工作空间之间数据隔离，但可以通过链接跨空间引用。

## 3. 优点

1. **自定义数据模型**：用户可以定义自己的对象类型和属性，灵活度极高。
2. **P2P 同步**：去中心化架构，不依赖中央服务器。
3. **零知识加密**：端到端加密，隐私保障强。
4. **本地优先**：完全离线可用，可靠性高。
5. **跨平台**：Windows、macOS、Linux、Android、iOS。
6. **gRPC API**：提供标准化的 API 供外部工具集成。

---

## 4. 独特之处

### 4.1 "Knowledge OS" 概念

Anytype 把自己定位为"操作系统"而非"应用"，这反映在设计上：

- 不只是笔记，还包括任务管理、联系人管理、项目管理、文件管理等多种能力。
- 所有这些能力统一在一个数据模型下——都是"对象"。
- 用户可以根据自己的需求组合不同的对象类型，创建个性化的"操作系统"。

### 4.2 基于 ObjectKit 的自定义

Anytype 的自定义能力深入到数据模型层面：

- **ObjectKit** 是 Anytype 的对象系统核心，允许用户：
  - 创建新的对象类型。
  - 定义类型的属性（类型、是否必填、默认值等）。
  - 定义类型的视图（列表视图、看板视图、日历视图等）。
  - 定义类型的行为（创建时自动设置某些属性等）。

这种级别的自定义在笔记应用中是罕见的。

### 4.3 开源 + 商业双重模式

Anytype 的核心协议和客户端都是开源的（GPL-3.0），但：

- P2P 同步的中继服务器是闭源的。
- 官方提供托管的 P2P 中继服务（付费）。
- 用户可以自建中继服务器（免费）。

这个模式保证了核心协议开放，同时维持商业可持续性。

## 6. 需要注意的教训

1. **学习曲线极高**：对象类型、P2P 同步、工作空间……概念密度大，新用户需要较长时间理解。
2. **性能问题**：P2P 同步和本地数据库在大数据量下有性能挑战。
3. **生态尚不成熟**：开源但功能仍在快速迭代中，部分功能不够稳定。
4. **中继服务器依赖**：虽然协议开源，但 P2P 同步的中继服务器是闭源的，存在一定的依赖风险。
5. **社区规模有限**：相比 Obsidian 和 Joplin，Anytype 的社区和文档资源较少。
