# QOwnNotes — 详细介绍

> 调研日期：2026-06-27

---

## 1. 设计哲学

QOwnNotes 的设计哲学非常纯粹：**"Plain-Text First"（纯文本优先）。**

它的核心信念是：笔记应该以**最基础、最开放、最持久的格式**存储——纯文本 Markdown 文件。任何其他格式（数据库、专有格式、云端格式）都是对数据主权的威胁。

这个哲学衍生出两个关键设计原则：

1. **资源消耗要低**：不用 Electron，不用 Chromium，用 C++/Qt 原生构建，启动快、内存少。
2. **与自托管生态深度整合**：主要目标用户是 Nextcloud/ownCloud 用户，同步和协作围绕这些平台设计。

---

## 2. 核心设计思路

### 2.1 纯文本 Markdown 文件存储

QOwnNotes 的所有笔记都以 `.md` 文件存储在本地文件夹中：

- 没有数据库层，没有序列化层。
- 你可以用任何文本编辑器打开、编辑、搜索这些文件。
- 文件命名和文件夹结构完全由用户决定。

**为什么这很重要？**

很多笔记应用声称"支持导出 Markdown"，但实际上它们的存储格式是私有的，导出只是一个"额外功能"。QOwnNotes 从第一天起就把 Markdown 文件作为**唯一的数据形态**——应用只是这些文件的"编辑器"，不是"所有者"。

### 2.2 Nextcloud/ownCloud 深度集成

QOwnNotes 的设计围绕 Nextcloud/ownCloud 生态展开：

- **笔记同步**：通过 Nextcloud 的 WebDAV 接口同步笔记文件。
- **任务同步**：Nextcloud 的 Tasks 应用中的待办事项可以直接在 QOwnNotes 中显示和管理。
- **实时编辑**：支持 Nextcloud 的 Collabora Online 集成，可以实时协作编辑笔记。

这个设计让 QOwnNotes 成为**自托管用户的首选笔记工具**——如果你已经在用 Nextcloud 做文件同步和任务管理，QOwnNotes 是最自然的补充。

### 2.3 脚本系统和 AI 集成

QOwnNotes 提供了一个基于 **Python 的脚本系统**：

- 用户可以编写 Python 脚本，在笔记事件中触发（如打开笔记时、保存笔记时）。
- 脚本可以读取笔记内容、修改笔记、调用外部 API。
- 社区贡献了大量现成脚本（自动生成目录、统计字数、发送通知等）。

**AI 集成**是 QOwnNotes 近年新增的重要功能：

- 支持 OpenAI GPT 和 Groq 模型的 API。
- 可以在笔记中直接调用 AI 生成内容、总结文本、翻译等。
- AI 功能通过脚本系统调用，保持了扩展性。

### 2.4 内置 MCP 服务器

QOwnNotes 最新的一个设计亮点是**内置 MCP（Model Context Protocol）服务器**：

- MCP 是一个开放协议，允许 AI 应用（如 Claude Desktop）直接访问外部工具和数据。
- QOwnNotes 的 MCP 服务器让外部 AI Agent 可以：
  - 搜索 QOwnNotes 中的笔记。
  - 读取指定笔记的内容。
  - 列出笔记文件夹结构。
- 这意味着：**你的 AI 助手可以直接"读懂"你的笔记库**。

**对 2notes 的启示**：2notes 的 AI 整理权限边界设计中，MCP 是一种标准化的"AI 访问笔记"的方式，比自定义 API 更安全、更可互操作。

### 2.5 浏览器伴侣扩展

QOwnNotes 提供了一个浏览器扩展：

- 在浏览器中选中文字，可以一键发送到 QOwnNotes 作为新笔记。
- 可以保存整个网页内容为笔记。
- 支持自定义模板（发送时自动套用格式）。

这个设计填补了"浏览器中获取信息 → 笔记应用中整理信息"之间的空白。

## 3. 优点

1. **极低的资源消耗**：C++/Qt 原生应用，启动时间在毫秒级，内存占用远低于 Electron 应用。
2. **数据完全可移植**：纯文本 Markdown 文件，任何工具都能打开。
3. **Nextcloud 生态深度整合**：自托管用户的首选。
4. **脚本系统灵活**：Python 脚本可以扩展几乎任何功能。
5. **内置 MCP 服务器**：AI Agent 可以直接访问笔记，标准化接口。
6. **AES-256 加密**：单篇笔记加密，细粒度隐私控制。

---

## 4. 独特之处

### 4.1 原生 C++ 的性能优势

在 Electron 主导的笔记应用市场中，QOwnNotes 坚持用 C++/Qt 构建，这带来了：

- **启动速度**：几乎瞬时启动，不需要等待 Chromium 初始化。
- **内存占用**：常驻内存通常只有 50-100MB，而同类 Electron 应用通常需要 200-500MB。
- **系统整合**：Qt 框架可以很好地融入各种桌面环境（KDE、GNOME 等）。

### 4.2 内置 MCP 服务器

QOwnNotes 是**首个内置 MCP 服务器的笔记应用**之一。MCP 是 Anthropic 提出的开放协议，目的是让 AI 应用可以安全地访问外部数据源。

QOwnNotes 的 MCP 服务器设计思路：

- 暴露有限的读取能力（搜索、读取、列出），不暴露写入能力。
- 用户可以配置哪些笔记目录对 AI 开放。
- AI Agent 通过 MCP 协议查询笔记，不需要知道笔记的存储格式。

这个设计让"AI 整理笔记"从一个应用内功能变成了一个**可插拔的服务**。

### 4.3 专注自托管生态

QOwnNotes 不追求"所有人都在用"，而是**专注于自托管用户群体**：

- 不和 Notion 比协作功能（因为目标用户不需要）。
- 不和 Obsidian 比插件生态（因为目标用户更看重稳定性）。
- 不和 Joplin 比同步后端多样性（因为目标用户已经选了 Nextcloud）。

这种聚焦让 QOwnNotes 在特定用户群体中获得了极高的忠诚度。

## 5. 值得借鉴的设计决策

| 决策 | 具体内容 | 对 2notes 的参考价值 |

| MCP 服务器 | AI Agent 标准化访问笔记 | 2notes AI 整理接口设计 |
| 脚本系统 | Python 脚本触发笔记事件 | 2notes 自动化可参考 |

| 原生性能 | C++ 低资源消耗 | 2notes 如果用 Electron 需注意性能 |
| 细粒度加密 | 单篇笔记加密 | 2notes 剪贴板隐私控制 |

## 6. 需要注意的教训

1. **UI 不够现代**：Qt 界面的美观度和交互流畅度不如 Electron 应用。
2. **跨平台一致性弱**：在不同桌面环境（KDE、GNOME、Windows）下表现不一致。
3. **移动端缺失**：没有官方移动端应用，不适合需要多端使用的用户。
4. **社区规模小**：用户基数和开发者社区都不大，脚本和插件数量有限。
5. **Nextcloud 依赖**：核心价值绑定在 Nextcloud 生态上，不用 Nextcloud 的用户感知价值降低。
